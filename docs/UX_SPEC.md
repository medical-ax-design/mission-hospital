# UX 및 화면 명세

## 1. UX 목표

### 의료진

- 검사·수술 이름을 알고 있으면 10초 안에 항목을 찾는다.
- 새 프로토콜 작성자는 현재 상태와 다음 행동을 항상 알 수 있다.
- 의료진은 준비가 정상인 환자보다 대응이 필요한 환자를 먼저 본다.

### 환자

- 첫 화면에서 지금 해야 할 일 하나를 이해한다.
- 텍스트 입력 없이 대부분의 작업을 완료한다.
- 잘 모르거나 수행하기 어려울 때 즉시 도움을 요청한다.

### 보호자

- 향후 릴리스에서 환자의 동의 이후 준비 상태를 공유받는다.
- 환자 대신 의료 판단을 하지 않고 수행을 보조한다.

## 2. 정보 구조

```text
의료진 웹
├─ 대시보드
│  ├─ 대응 필요
│  ├─ 진행 중
│  └─ 준비 완료
├─ 환자 준비 케이스
│  ├─ 새 케이스
│  └─ 케이스 상세
├─ 검사·수술 카탈로그
│  ├─ 검색
│  ├─ 항목 등록
│  └─ 항목 상세
├─ 준비 프로토콜
│  ├─ 초안 편집
│  ├─ 미리보기
│  └─ 버전 이력
└─ 감사 로그

환자 모바일
├─ 데모 로그인
├─ 현재 할 일
├─ 전체 준비 일정
├─ 완료 내역
└─ 도움 요청
```

## 3. 의료진 핵심 흐름

### 3.1 카탈로그 검색 및 등록

```text
카탈로그 목록
→ 검색어 입력
→ 결과 확인
├─ 기존 항목 선택
└─ 결과 없음
   → 새 항목 등록
   → 검사·수술 구분
   → 이름·부서 입력
   → 외부 코드 선택 입력
   → 저장
```

검색 필드:

- placeholder: `검사·수술 이름 또는 코드 검색`
- 입력 후 300ms 디바운스
- 2글자부터 서버 검색
- Enter로 첫 결과 이동

결과 행:

```text
대장내시경
검사 · 소화기내과 · 코드 미등록
게시 프로토콜 v2
```

빈 상태:

```text
‘대장내시경’과 일치하는 항목이 없습니다.
[이 이름으로 새 항목 등록]
```

중복 의심:

```text
비슷한 항목이 있습니다.
- 건강검진 대장내시경 · 건강의학센터
- 치료 대장내시경 · 소화기내과

[기존 항목 보기] [그래도 새로 등록]
```

### 3.2 프로토콜 작성

화면은 세 영역으로 구성한다.

```text
┌─────────────────────────────────────┐
│ 대장내시경 준비 프로토콜 v1 · 초안     │
├──────────────┬──────────────────────┤
│ 단계 목록      │ 선택한 단계 편집          │
│ 3일 전         │ 제목                     │
│ 전날 저녁      │ 환자 안내                 │
│ 검사 당일      │ 기준 시각·응답 방식        │
│ + 단계 추가    │ 도움 안내                 │
├──────────────┴──────────────────────┤
│ [환자 화면 미리보기] [초안 저장] [게시] │
└─────────────────────────────────────┘
```

작성 규칙:

- 자동 저장 상태를 표시한다.
- 순서는 드래그 외에 위·아래 버튼으로도 바꿀 수 있다.
- 단계 삭제는 게시 전 초안에서만 가능하다.
- 시간 오프셋은 자연어와 절대값을 함께 표시한다.

예:

```text
검사 3일 전 오전 9시
기준값: -72시간
```

게시 전 검증:

- 제목 누락
- 단계 없음
- 같은 순서값
- 환자 설명 누락
- 응답 방식 누락
- 기한이 검사 이후인데 사후 단계가 아닌 경우

### 3.3 프로토콜 게시 확인

게시 행동은 영향이 크므로 확인 화면을 사용한다.

```text
대장내시경 준비 프로토콜 v1을 게시하시겠습니까?

- 게시 후 내용을 직접 수정할 수 없습니다.
- 이후 생성되는 환자 케이스에 적용됩니다.
- 현재 진행 중인 환자 케이스는 변경되지 않습니다.

[취소] [게시]
```

### 3.4 환자 케이스 생성

프로토타입 입력:

- 가상 환자 계정
- 가상 환자 표시명
- 연령 표시용 값
- 검사·수술 항목
- 예정 일시

선택 결과:

```text
대장내시경
적용 프로토콜: v1 · 2026-07-29 게시
생성 작업: 4개
첫 작업 시작: 지금
```

게시 프로토콜이 없을 때:

```text
이 검사에는 게시된 준비 프로토콜이 없습니다.
환자 안내를 임의로 생성하지 않습니다.

[프로토콜 만들기] [취소]
```

### 3.5 의료진 대시보드

상단 요약:

```text
내일 예정 20명
확인 필요 1 · 도움 요청 2 · 지연 3 · 준비 완료 14
```

목록 정렬:

1. `NEEDS_REVIEW`
2. `HELP_REQUESTED`
3. `OVERDUE`
4. `NOT_STARTED`
5. `IN_PROGRESS`
6. `READY`

환자 행:

```text
김환자 · 68세(가상)
대장내시경 · 내일 10:00
도움 요청 · 장정결제 복용방법
마지막 응답 12분 전
[확인]
```

목록은 색상과 함께 텍스트 상태를 표시한다.

## 4. 환자 핵심 흐름

프로토타입은 PATIENT 역할의 가상 계정으로 로그인한다. 실제 환자용 로그인·본인확인·보호자 연결은 구현하지 않는다.

### 4.1 현재 할 일

```text
┌──────────────────────┐
│ 내일 오전 10:00 대장내시경 │
│ 준비 2/4              │
├──────────────────────┤
│ 지금 해야 할 일          │
│                      │
│ 장정결제 1차분을         │
│ 안내받은 용량대로 드세요. │
│                      │
│ [완료했습니다]           │
│ [도움이 필요해요]        │
├──────────────────────┤
│ 전체 준비 일정 보기       │
└──────────────────────┘
```

원칙:

- 주요 버튼은 한 화면에 최대 2개
- 긴 설명은 `자세히 보기`로 분리
- 의료진 연락이 필요한 상황과 긴급 상황 안내를 구분
- 환자에게 내부 코드, 프로토콜 버전, 시스템 상태를 노출하지 않음

### 4.2 도움 요청

자유 입력 대신 선택형으로 시작한다.

```text
어떤 도움이 필요한가요?

○ 안내를 이해하기 어려워요
○ 준비물을 구하지 못했어요
○ 정해진 시간에 수행하지 못했어요
○ 복용 중인 약 때문에 확인이 필요해요
○ 기타 의료진 확인이 필요해요

[요청 보내기]
```

주의문:

> 이 기능은 응급상황 신고나 실시간 의료상담이 아닙니다. 심한 증상이나 긴급한 상황은 병원에서 안내받은 연락처 또는 응급의료체계를 이용하세요.

### 4.3 전체 일정

```text
완료  검사 3일 전 음식 확인
완료  전날 저녁 식사
현재  장정결제 1차 복용
예정  장정결제 2차 복용
예정  병원 도착
```

미래 단계는 미리 볼 수 있지만 현재 행동보다 시각적 우선순위를 낮춘다.

## 5. 상태 문구

| 내부 상태 | 의료진 문구 | 환자 문구 |
|---|---|---|
| PENDING | 시작 전 | 예정된 준비 |
| AVAILABLE | 수행 가능 | 지금 해야 할 일 |
| COMPLETED | 완료 | 완료했습니다 |
| OVERDUE | 기한 경과 | 예정 시간이 지났습니다 |
| HELP_REQUESTED | 도움 요청 | 도움 요청을 보냈습니다 |
| NEEDS_REVIEW | 의료진 확인 필요 | 의료진 확인을 기다리고 있습니다 |
| CANCELLED | 취소 | 취소된 준비 |

## 6. 오류와 복구

### 네트워크 오류

- 제출 버튼을 즉시 연속 클릭하지 못하게 한다.
- 실패 시 입력을 유지한다.
- 재시도 행동과 오류 추적 ID를 표시한다.

### 중복 제출

- 클라이언트가 idempotency key를 보낸다.
- 서버가 같은 키의 성공 결과를 반환한다.

### 세션 만료

- 작성 중인 초안은 로컬 임시 저장한다.
- 로그인 후 서버 최신 버전과 비교한다.
- 충돌 시 자동 덮어쓰지 않는다.

### 동시 편집

- `row_version`이 다르면 저장을 거부한다.
- 서버 최신본과 내 변경을 비교할 수 있게 한다.

## 7. 반응형 기준

- 환자 화면: 360px 이상 모바일 우선
- 의료진 화면: 1024px 이상 데스크톱 우선, 768px까지 읽기 가능
- 의료진 테이블은 작은 화면에서 카드 목록으로 전환
- 환자 핵심 버튼은 하단 안전영역을 고려

## 8. 접근성 체크리스트

- 키보드만으로 의료진 주요 흐름 완료
- 포커스 표시 유지
- 폼 오류를 필드 옆과 상단 요약에 동시 표시
- 의미 있는 제목 구조 사용
- 아이콘에 텍스트 또는 접근 가능한 이름 제공
- 모션 감소 설정 존중
- 환자 화면의 기본 본문 크기 18px 이상 권장
- 전문용어에는 쉬운 설명 병기
