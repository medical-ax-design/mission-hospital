# Wait:ON 보호자 동행 UX 명세

## 1. UX 목표

- 보호자가 첫 화면에서 현재 상태, 지금 할 일, 다음 안내를 순서대로 이해한다.
- 병원 이용 경험이 없어도 업무 목적에서 처리 장소와 이동 순서를 찾는다.
- 실제 병원 확인 정보와 일반 교육 정보를 혼동하지 않는다.
- 날짜별 일정과 이동 목적지를 한 흐름에서 찾는다.
- 40대 이상 보호자와 고령 환자가 큰 조작 영역과 최소 입력으로 사용한다.

## 2. 정보 구조

```text
환자 연결
└─ 보호자 홈
   ├─ 홈
   │  ├─ 치료 진행 상세
   │  └─ 보호자 업무
   ├─ 일정
   │  └─ 날짜별 진료·검사·입원·수술
   └─ 이용 안내
      ├─ 목적 기반 이용 안내
      │  ├─ 서류 발급 → 온라인·모바일·병원 방문 방법
      │  └─ 방문 장소 → 해당 건물·층 공식 안내도
      ├─ 전체 건물·층별 안내
      │  └─ 본관·별관·암병원·양성자치료센터
      └─ 검사 준비·주의사항
         ├─ 음식·행동 검색
         └─ 의료진 질문 목록
```

가상 시나리오 선택은 홈의 발표자 보조 영역에 표시한다. 위암 수술 단계
제어는 치료 진행 상세 화면에만 표시한다. 두 도구 모두 `?demo=1`에서만
나타난다.

## 3. 전체 사용자 흐름

```text
가상 환자 확인
→ 보호자로 연결하기
→ 수술 준비 중 확인
├─ 과정 알아보기 → 병원 확인 상태 / 일반 과정 → 홈
├─ 입원 서류 발급 → 공식 처리 방법 → 온라인·모바일·방문 장소
├─ 일정 → 환자 아이콘이 있는 날짜 → 일정·장소·준비사항
└─ 이용 안내 → 목적 선택 또는 전체 층 안내
   → 건물·층·공식 시설 확인
   ├─ 공개자료: 공식 지도와 시설 위치만 확인
   └─ 병원 승인 경로: 층별 2D 복도선 → 층 전환 → 다음 층 복도선
```

## 4. 화면 명세

모든 화면은 최대 430px 모바일 셸, 네이비 상단 헤더, 20px 콘텐츠 여백,
20px 카드 모서리와 동일한 고정 하단 메뉴를 공유한다. 홈은 넓은 히어로
헤더를 사용하고 하위 화면은 동일한 브랜드 앱 바를 사용한다.

### S1. 환자 연결

목적: 보호자가 보고 있는 환자와 관계를 확인하고 데이터 접근 경계를 설명한다.

필수 요소:

- `환자를 선택해 주세요`
- 가상 환자 이름, 연령, 치료명, 보호자 관계
- 환자 동의·보호자 본인 확인에 대한 운영 원칙
- 발표용 가상 환자 정보 문구
- `보호자로 연결하기`

주요 행동 성공 후 API 응답의 `linked: true`를 확인하고 홈으로 이동한다.

### S2. 보호자 홈

읽기 순서:

1. 환자와 치료명
2. 병원이 확인한 현재 단계
3. 다음 상태 알림 조건
4. 지금 할 보호자 업무
5. 다음 안내
6. 하단 주요 메뉴

홈 상단에는 보호자 인사와 병원 이용 목적 검색을 제공한다. 목적 검색은
의료 질문을 처리하지 않고 서류 발급·검사실 이동·수납 등 공식 이용
안내만 검색한다. 홈 하단에는 오늘 일정 최대 세 개와 전체 일정 진입을
표시한다.

현재 상태 카드에는 `병원 확인` 출처를 표시한다. 예상 종료시각은 표시하지 않는다.

### S3. 치료 진행 상세

화면은 다음 읽기 순서를 유지한다.

1. `병원 확인 상태`
2. AI 치료 과정 미디어 카드
3. `일반적인 수술 과정` 타임라인

AI 카드는 `AI로 재구성한 일반 과정`과 `현재 환자의 실시간 영상이
아닙니다`를 상시 표시한다. 현재 단계의 비자극적 장면, 단계명과 한 문장
설명을 제공하되, 병원 확인 상태를 변경·예측하거나 검증하지 않는다.
영상 재생이 불가능하면 정지 포스터를 표시하고, 포스터도 불러오지 못하면
단계명이 있는 기본 장면을 표시한다.

일반 과정:

1. 수술 준비
2. 수술실 입실
3. 수술 진행
4. 회복실
5. 병실 이동

현재 단계에는 번호, 텍스트, `현재 확인 단계`, `aria-current="step"`을 제공한다. 하단에 일반 설명이 실제 치료 판단이나 예상시간이 아님을 표시한다.

### S4. 보호자 업무

필수 요소:

- 업무명
- 현재 확인된 준비물
- 서류 종류와 신청자 관계에 따라 조건이 달라질 수 있다는 안내
- `공식 처리 방법 확인`

확인되지 않은 예상 소요시간, 번호표와 창구번호는 표시하지 않는다.
한 화면에서 가장 중요한 행동은 공식 처리 방법 확인 하나다.

### S5. 목적 기반 병원 이용 가이드

필수 요소:

- 사용 목적 검색과 `서류 발급` 바로가기
- 온라인·모바일·병원 방문 처리 방법
- 공식 안내에서 확인한 준비물과 순서
- 병원 방문 선택지의 건물·층·시설번호
- 공식 발급 안내 원문
- `이 장소로 안내`

방문보다 온라인·모바일 처리를 먼저 확인하도록 순서를 구성한다.
사용자가 위치보다 목적을 먼저 선택했다는 맥락을 유지한다.

### S6. 환자 일정

- `홈 / 일정 / 이용 안내` 하단 메뉴에서 진입한다.
- 상단에 선택 날짜 요약과 선택 날짜를 중심으로 한 5일 날짜 스트립을
  표시한다.
- 날짜 버튼은 실제 버튼과 `aria-pressed`를 사용하며 선택 즉시 날짜
  제목, 일정 수와 목록을 함께 갱신한다.
- 기존 월간 달력은 `달력 보기`로 펼치거나 접는다.
- 일정이 있는 날짜에는 환자 표식을 표시하고 일정 개수를 접근 가능한
  이름으로 제공한다.
- 날짜를 선택하면 시간, 일정명, 건물·층·장소와 준비사항을 표시한다.
- 일정이 없으면 `등록된 병원 일정이 없습니다`를 표시한다.
- 다른 날짜의 일정을 빈 날짜에 복사하지 않으며 초기 날짜로 돌아가는
  행동을 제공한다.

### S7. 병원 이용 안내

- 목적 기반 이용 안내와 `전체 건물·층별 안내`를 분리한다.
- 건물 탭은 본관·별관·암병원·양성자치료센터를 제공한다.
- 지하층은 `지하 1층`처럼 텍스트로 표시한다.
- 선택한 층에서 공식 안내도, 확인된 시설번호·시설명과 원문 링크를
  제공한다.
- 검사 준비 안내가 등록되지 않은 환자에게는 빈 상태를 보여주고
  의료지침을 만들지 않는다.

### S8. 병원 안 길찾기

- `MAP_ONLY`: 공식 안내도와 목적 시설을 표시하고 선과 사용자
  애니메이션은 기본적으로 표시하지 않는다.
- 발표 프로토타입에서는 암병원 1층의 내시경실·원무수납·
  의무기록복사 목적지만 예외로 제공한다. 사용자가 지도에서 현재
  복도나 출입구를 누르면 가장 가까운 시연 복도 노드에 맞추고
  목적지까지의 붉은 선을 같은 지도 SVG 계층에 표시한다.
- 시연 복도에서 먼 방 내부 선택은 거부하고 재선택을 요청한다.
- 이 예외는 `공식 지도 기반 길찾기 시연`과 `현장 검증 필요`를
  함께 표시하며 병원 승인 경로로 표현하지 않는다.
- `VERIFIED`: 병원이 승인한 2D 평면과 그 버전에 대응하는 복도
  노드가 있을 때만 실제 지도 내부에 선을 표시한다.
- 현재 층 선은 실제 엘리베이터·에스컬레이터 입구에서 끝낸다.
- 층 이동은 지도와 선이 없는 별도 전환 화면으로 표시한다.
- 도착 층 선은 실제 출구에서 새로 시작한다.
- 에스컬레이터는 연결 층, 방향과 운행 상태가 확인된 경우에만
  제공한다.
- `UNAVAILABLE`: 지도나 경로를 추측하지 않고 안내 데스크 문의를
  표시한다.
- 3D 지도는 필수가 아니다. 모바일에서는 복도와 출입구가 읽히는
  단순한 2D 평면을 우선한다.

## 5. 발표자 흐름

발표 URL: `http://localhost:3000/?demo=1`

홈에서는 위암 수술과 대장내시경 가상 시나리오를 선택한다. 위암 수술의
치료 진행 상세 화면에서만 하단 고정 제어 막대를 표시하고 이전·다음,
현재 단계 번호와 자동 진행 시작·정지를 제공한다.

수술 데모 단계는 브라우저 `sessionStorage`에만 저장하며 병원 상태 API를
호출하거나 변경하지 않는다. 단계 변경 시 `발표용 병원 상태 시연`, AI
미디어와 타임라인을 함께 갱신한다. 자동 진행은 8초 간격이며 마지막
단계에서 정지하고 `다음`을 비활성화한다. 일반 사용 URL에는 이 제어
막대를 렌더링하지 않는다.

## 6. 콘텐츠 규칙

- `예상`, `곧`, `정상`처럼 병원이 확인하지 않은 판단 표현을 사용하지 않는다.
- 상태는 `병원 확인`, 교육은 `이해를 돕는 안내`로 출처를 표시한다.
- 내부 코드와 시스템 상태명을 사용자에게 노출하지 않는다.
- 한 문장에는 한 행동만 담는다.
- 의료용어는 쉬운 한국어를 우선하고 필요한 경우 원어를 병기한다.

치료 단계와 일정은 가상 데이터다. 지도 이미지는 삼성서울병원 공식
공개 안내다. 암병원 1층의 붉은 선은 발표용 시연 그래프이며 현재
운영 데이터나 병원 승인 경로가 아니다.

## 7. 접근성·반응형

- 최소 지원 폭: 320px, 기준 검증 폭: 390px
- 720px 이하: 테두리 없는 전체 화면
- 720px 초과: 최대 430px 모바일 셸 중앙 배치
- 모든 주요 버튼 최소 높이 48px
- 본문 최소 16px, 보조 문구 최소 14px
- `:focus-visible` 3px 고대비 외곽선
- 색상 외에 텍스트와 기호로 상태 전달
- 의미 있는 `h1`·`h2`, 목록, 영역 라벨 사용
- 모션 감소 설정에서 로딩·경로·층 전환 애니메이션과 AI 포스터 모션,
  치료 단계 자동 진행 제거
- 하단 치료 단계 제어가 마지막 안내를 가리지 않도록 충분한 여백 확보

## 8. 오류와 복구

- 초기 로딩: `보호자 정보를 확인하고 있습니다`
- 조회 실패: `정보를 불러오지 못했습니다` + `다시 시도`
- 변경 요청 중: 버튼 비활성화와 진행 문구
- 공개 지도 전용: `공식 지도에서 위치를 확인하세요` + 원문 링크
- 암병원 1층 시연: `지도에서 현재 위치를 선택하세요` + 현장 검증
  필요 안내
- 경로 없음: `확인된 이동 안내가 없습니다` + 안내 데스크 문의
- API 응답 계약 오류: 일반 조회 실패 상태로 전환
- AI 영상 실패: 단계별 정지 포스터와 설명 유지
- AI 포스터 실패: 단계명이 있는 기본 장면과 설명 유지
- 검색·질문 변경 실패: 현재 화면과 입력을 유지하고 같은 행동을
  다시 시도할 수 있는 인라인 오류 표시

## 9. 사용성 검증 질문

1. 현재 환자가 어디까지 진행됐다고 이해했는가?
2. 지금 보호자가 해야 할 일은 무엇인가?
3. 온라인·모바일로 먼저 처리할 수 있는가?
4. 병원 방문 시 어느 건물·층·시설로 가야 하는가?
5. 어떤 내용이 실제 병원 확인이고 어떤 내용이 일반 설명인가?
6. 일정이 있는 날짜와 목적지를 찾을 수 있는가?
7. 공개 지도와 병원이 검증한 경로의 차이를 이해하는가?
8. 경로가 제공될 때 층 전환 후 다음 지도에서 새로 시작함을
   이해하는가?

## 10. 대장내시경 제한 안내 흐름

```text
발표자 도구에서 대장내시경 여정 선택
→ 보호자로 연결
→ 홈의 현재 주의사항 확인
→ 지금 피해야 할 것 보기
├─ 현재 단계 제한과 공식 출처 확인
├─ 음식·행동 검색
│  ├─ 명시적 제한 → 지금은 제공하지 마세요
│  └─ 규칙 없음 → 확인 전에는 제공하지 마세요
└─ 질문으로 저장 → 질문 목록 → 확인 완료
```

### S9. 홈 현재 주의사항

- 치료 상태와 보호자 업무 사이에 표시한다.
- `검사 3일 전`처럼 현재 적용 단계를 텍스트로 표시한다.
- 핵심 제한 문장과 적용 기간을 함께 표시한다.
- 주요 행동은 `지금 피해야 할 것 보기` 하나다.

### S10. 제한 상세와 검색

- 화면 제목은 `지금 피해야 할 것`이다.
- 현재 단계에 적용되는 제한만 목록으로 표시한다.
- 제한 상태는 색상 외에 `지금은 제공하지 마세요` 또는
  `확인 전에는 제공하지 마세요` 문구로 구분한다.
- 검색 결과에는 이유, 적용 기간과 공식 안내 원문 링크를 제공한다.
- 검색 결과가 없더라도 허용으로 해석하지 않고 확인 필요로 표시한다.
- 검사 당일 절대 금식은 오전 5시부터로 표시한다.

### S11. 의료진에게 확인할 질문

- 열린 질문과 확인 완료 질문을 한 목록에서 구분한다.
- `확인 완료`는 답변 내용이 아니라 상담 여부만 기록한다.
- 열린 질문과 확인 완료 질문 모두 삭제할 수 있다.
- 질문은 자동 전송되지 않는다는 문구를 화면에 고정한다.
- 자유서술 의료정보 입력란은 제공하지 않는다.

## 11. 제한 안내 콘텐츠 규칙

- `먹어도 됩니다`, `안전합니다`, `문제없습니다`를 사용하지 않는다.
- 병원 승인 자료에서 명시한 제한과 앱의 확인 필요 결과를 구분한다.
- 약 검색은 복용 지시를 만들지 않고 예약 안내와 의료진 확인을
  요청한다.
- 공식 출처 제목, 확인일과 데이터 버전을 표시한다.

## 12. 구현된 원내 안내 UX

```text
보호자 업무 또는 이용 안내
→ 목적 선택
→ 공식 처리 방법 확인
→ 병원 방문 장소 선택
→ 해당 건물·층 공식 안내도와 시설 확인
→ 공식 원문 또는 안내 데스크 확인
```

현재 프로토타입은 `MAP_ONLY`다. 공식 3D 안내 이미지는 시설 위치를
확인하는 참고 자료로 사용하지만 그 위에 임의의 선을 합성하지 않는다.
제품화 단계에서는 병원이 승인한 2D 평면과 복도 그래프를 연결한다.

- 현재 위치를 자동 감지했다고 오인시키지 않는다.
- 검증 경로가 도입되면 출발 층 복도, 이동 수단, 도착 층 복도를
  서로 다른 화면으로 보여준다.
- 공식 원문 링크와 자료 확인 기준을 표시한다.
- 공사나 폐쇄 정보가 만료되었으면 길을 생성하지 않고 안내 데스크
  확인을 요청한다.
- 접근성 경로는 병원 내부 검증 데이터가 있을 때만 제공한다.
