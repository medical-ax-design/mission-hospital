# AI 치료 진행 미디어 설계

- 작성일: 2026-07-30
- 상태: 승인
- 대상: 보호자용 치료 진행 상황 화면
- 범위: 위암 수술 데모 시나리오의 5단계 치료 흐름

## 1. 목표

보호자가 수술을 기다리는 동안 병원이 확인한 현재 치료 단계를 글로만
읽는 대신, 비자극적인 AI 재구성 장면으로 직관적으로 이해하도록 돕는다.

영상은 현재 환자의 실제 모습이나 수술실 CCTV가 아니다. 병원 시스템에서
받은 치료 상태가 유일한 기준이며, AI 미디어는 그 상태를 설명하는 보조
콘텐츠로만 사용한다.

## 2. 핵심 원칙

1. `병원 확인 상태`를 AI 미디어보다 먼저 보여준다.
2. AI 사용 사실을 영상 카드 안에 항상 표시한다.
3. 현재 환자의 실시간 영상이 아니라는 문구를 항상 표시한다.
4. 출혈, 절개, 장기, 수술 부위, 환자 얼굴 등 자극적인 장면을 만들지 않는다.
5. 예상 종료 시간이나 치료 결과를 영상으로 암시하지 않는다.
6. 영상이 없거나 재생되지 않아도 상태 확인과 전체 기능을 사용할 수 있어야 한다.

## 3. 화면 구조

치료 진행 화면은 다음 순서로 구성한다.

1. 페이지 제목
2. 병원 확인 상태 카드
3. AI 치료 과정 미디어 카드
4. 일반적인 수술 과정 타임라인
5. 안내 정보 고지
6. 데모 모드에서만 노출되는 하단 고정 제어 막대

### 3.1 AI 치료 과정 미디어 카드

카드에는 다음 요소를 표시한다.

- 상단 배지: `AI로 재구성한 일반 과정`
- 현재 단계에 맞는 비자극적 장면
- 단계명과 한 문장 설명
- 상시 고지: `현재 환자의 실시간 영상이 아닙니다`
- 재생 또는 일시정지 버튼

미디어는 무음, 인라인, 반복 재생을 기본으로 한다. 장면 전환에는 짧은
페이드 효과만 사용하며, 섬광이나 빠른 카메라 이동은 사용하지 않는다.

## 4. 단계별 장면

| 치료 단계 | 화면 문구 | 비자극적 AI 장면 |
| --- | --- | --- |
| `PREPARING` | 수술 준비 중 | 정돈된 수술실 앞 공간, 체크리스트와 장비 준비 |
| `IN_OPERATING_ROOM` | 수술실 입실 | 수술실 복도와 닫힌 출입문, 입실 완료 표시 |
| `IN_PROGRESS` | 수술 진행 중 | 수술실 외부 표시등과 프라이버시 유리 너머 의료진 실루엣 |
| `RECOVERY` | 회복실 이동 | 차분한 회복 공간과 일반적인 관찰·확인 표현 |
| `COMPLETED` | 수술 일정 종료 | 병실 이동을 준비하는 조용한 복도와 병실 안내 |

모든 장면은 특정 병원 내부나 실제 의료 행위를 재현한 것으로 오인되지
않도록 일반화된 공간으로 제작한다.

## 5. MVP 미디어 전략

MVP는 `AI 이미지 기반 모션 장면 + 영상 파일 대체 구조`로 구현한다.

- 각 단계에 일관된 스타일의 AI 포스터 이미지를 제공한다.
- 포스터에 느린 확대, 조명 변화, 상태 표시 움직임 등 잔잔한 모션을 적용한다.
- 향후 생성형 AI 영상 파일을 확보하면 동일한 카드에 WebM/MP4 파일만
  연결하여 교체할 수 있게 한다.
- 영상 로딩 실패, 데이터 절약 환경, 동작 줄이기 설정에서는 AI 포스터를
  정지 상태로 보여준다.

미디어 메타데이터는 환자 상태 계약에 넣지 않고 프런트엔드의 단계별
콘텐츠 맵으로 관리한다. 병원 상태 데이터와 설명용 콘텐츠의 책임을
분리하기 위해서다.

예상 콘텐츠 항목은 다음과 같다.

```ts
interface TreatmentStageMedia {
  stage: TreatmentStage;
  title: string;
  description: string;
  posterSrc: string;
  videoSources?: Array<{
    src: string;
    type: 'video/webm' | 'video/mp4';
  }>;
  motionVariant: 'prepare' | 'entry' | 'operation' | 'recovery' | 'transfer';
}
```

## 6. 데모 단계 전환

`?demo=1`로 접속한 치료 진행 화면에서는 하단 고정 제어 막대를 항상
노출한다. 일반 접속에서는 이 막대를 렌더링하지 않는다.

제어 막대는 다음 기능을 제공한다.

- 이전 단계
- 다음 단계
- 현재 단계 번호(예: `2 / 5`)
- 자동 진행 시작 또는 정지

단계가 변경되면 아래 항목이 하나의 상태 전환으로 함께 바뀐다.

- 병원 확인 상태 문구
- AI 미디어 장면과 설명
- 수술 과정 타임라인의 현재 단계

발표용 상태는 브라우저 `sessionStorage`에만 저장한다. 공개된 데모를
여러 사람이 동시에 조작하더라도 서로의 화면에 영향을 주지 않으며,
실제 병원 상태 API를 변경하지 않는다.

자동 진행은 8초마다 다음 단계로 이동하고 마지막 단계에서 정지한다.
사용자가 이전·다음 버튼을 누르면 자동 진행을 해제한다. 브라우저 탭이
비활성화되면 자동 진행을 일시정지한다.

## 7. 접근성과 사용성

- `prefers-reduced-motion: reduce`에서는 모션과 자동 재생을 중단한다.
- 영상에만 중요한 정보를 넣지 않고 단계명과 설명을 텍스트로 제공한다.
- 재생·정지 버튼에는 명확한 접근성 이름을 제공한다.
- 자동 진행 상태는 텍스트와 버튼 상태로 함께 알린다.
- 고령 사용자도 누르기 쉽도록 제어 버튼의 최소 높이를 44px로 유지한다.
- 영상 카드와 제어 막대가 기존 글자 확대 및 모바일 레이아웃을 가리지
  않도록 하단 여백을 확보한다.

## 8. 오류 및 대체 동작

- 영상 파일 로딩 실패: AI 포스터와 단계 설명 표시
- 포스터 로딩 실패: 색상과 아이콘으로 구성한 단계별 기본 장면 표시
- 알 수 없는 치료 단계: 현재 병원 상태 문구는 유지하고 일반 안내 장면 표시
- 저장된 데모 단계 값 오류: API에서 받은 초기 단계로 복구

오류가 발생해도 병원 확인 상태, 타임라인, 안내 문구는 사라지지 않는다.

## 9. 검증 기준

1. 다섯 단계마다 올바른 미디어와 설명이 표시된다.
2. AI 사용 고지와 실시간 영상이 아니라는 고지가 항상 보인다.
3. 일반 접속에서는 데모 제어 막대가 보이지 않는다.
4. `?demo=1`에서는 제어 막대가 항상 보인다.
5. 이전·다음·자동 진행 시 상태 카드, 미디어, 타임라인이 함께 변경된다.
6. 데모 단계 변경이 서버의 치료 상태를 변경하지 않는다.
7. 동작 줄이기 환경에서는 정지 포스터가 표시된다.
8. 영상과 포스터가 실패해도 치료 상태를 확인할 수 있다.

## 10. 비범위

- 실제 수술실 CCTV 또는 환자 영상 연동
- 치료 예상 종료 시간 예측
- 환자별 수술 장면 생성
- AI가 병원 치료 상태를 추론하거나 변경하는 기능
- 특정 환자의 의학적 상태 또는 수술 결과를 영상으로 표현하는 기능
