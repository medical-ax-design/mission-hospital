# 검사·수술 준비 오케스트레이션 서비스 설계

## 상태

- 설계 승인일: 2026-07-29
- 승인 범위: 제품 흐름, 핵심 데이터 모델, Vercel·OCI·Supabase 아키텍처
- 다음 단계: 사용자 문서 검토 후 구현 계획 작성

## 문제

환자는 검사·수술 전에 여러 시점의 준비사항을 수행해야 하지만 안내가 분산돼 있고 조건별 차이가 크다. 고령 환자는 긴 안내와 복잡한 화면을 사용하기 어렵고, 보호자와 의료진은 준비 상태를 늦게 확인할 수 있다.

## 해결

병원이 승인한 검사·수술 준비 프로토콜을 시간순 작업으로 관리한다. 환자는 지금 할 일 하나를 수행하고, 의료진은 미확인·기한 경과·도움 요청 환자만 우선 확인한다.

## 핵심 결정

### 카탈로그

- 검사·수술 항목은 UUID `id`를 기본키로 가진다.
- 이름은 필수다.
- 병원 외부 코드는 선택값이다.
- 검색은 이름, 코드와 부서를 지원한다.

### 프로토콜

- 한 Procedure에 여러 버전이 존재할 수 있다.
- 동시에 게시된 버전은 하나다.
- 게시된 버전은 불변이다.
- 변경은 새 초안 버전으로 수행한다.

### 자동 적용

- 환자 일정 생성 시 현재 게시 프로토콜을 찾는다.
- 프로토콜 단계의 환자 표시 내용을 Case Task로 복사한다.
- 기존 환자 케이스는 후속 프로토콜 변경의 영향을 받지 않는다.
- 게시 프로토콜이 없으면 안내를 임의 생성하지 않는다.

### 사용자

- ADMIN: 카탈로그와 프로토콜 작성·게시
- STAFF: 환자 케이스와 예외 대응
- PATIENT: 본인 작업 수행과 도움 요청

### 의료 안전

- AI가 의료지침을 생성·변경·승인하지 않는다.
- 준비 작업 완료와 임상적 검사 가능 판정을 구분한다.
- 프로토타입에는 가상 환자와 가상 병원 지침만 사용한다.
- 모든 중요한 변경을 감사 로그에 기록한다.

## 화면

의료진:

1. 로그인
2. 예외 대시보드
3. Procedure 검색·등록
4. 프로토콜 단계 편집·미리보기·게시
5. 가상 환자 케이스 생성
6. 케이스 상세와 도움 요청 처리

환자:

1. 현재 할 일
2. 전체 준비 일정
3. 완료
4. 도움 요청

## 아키텍처

```text
Next.js / Vercel
        │ HTTPS + Supabase JWT
        ▼
NestJS REST API / OCI Docker
        │ PostgreSQL SSL
        ▼
Supabase PostgreSQL

Supabase Auth → JWT → NestJS 검증
```

브라우저는 인증을 제외한 핵심 도메인 쓰기를 NestJS API에 요청한다.

## 핵심 트랜잭션

### 프로토콜 게시

기존 게시 버전 종료, 새 버전 게시와 감사 로그 기록을 하나의 트랜잭션으로 처리한다.

### 케이스 생성

환자 케이스와 전체 Case Task 스냅샷 생성을 하나의 트랜잭션으로 처리한다.

## 실패 처리

- 프로토콜 없음: 케이스 생성 차단
- 동시 편집: 409와 최신 row version 반환
- 중복 제출: Idempotency-Key로 기존 결과 반환
- 세션 만료: 로그인 후 초안 충돌 확인
- 네트워크 오류: 입력 유지와 재시도

## 테스트

- 상태 전환 단위 테스트
- PostgreSQL 제약조건 통합 테스트
- 역할·조직 접근 테스트
- 게시·스냅샷 E2E
- 고령 사용자 중심 모바일 사용성 테스트

## 4일 범위

대장내시경 한 개의 준비 프로토콜을 완성하고, 가상 환자의 완료와 도움 요청이 의료진 대시보드에 반영되는 폐쇄 루프를 배포한다.
