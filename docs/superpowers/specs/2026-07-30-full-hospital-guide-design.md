# Wait:ON 전체 병원 이용 안내 고도화 설계

- 작성일: 2026-07-30
- 상태: 사용자 방향 승인, 구현 전 설계
- 대상: 삼성서울병원 보호자용 Wait:ON

## 1. 배경

현재 앱은 발표 시나리오에 필요한 일부 지도만 등록한다.

- 본관: 1F, 2F
- 별관: 1F, 2F
- 암병원: 1F, 2F, 3F

이 구성은 실제 삼성서울병원의 전체 층 안내처럼 보이지만 지하층과
고층이 빠져 있다. 또한 현재 붉은 이동선은 병원 공간 데이터에서
계산한 경로가 아니라 수동 좌표이므로 실제 길찾기로 사용할 수 없다.

이번 고도화는 이용 안내의 첫 진입을 `목적 기반 바로 연결`로
유지하면서, 모든 화면에서 `전체 건물·층별 안내`로 확장할 수 있는
구조를 만든다.

## 2. 목표

1. 보호자가 서류 발급·수납·검사·복약처럼 해야 할 업무를 먼저
   선택한다.
2. 공식 자료로 확인된 처리 방법, 준비물과 방문 장소만 제시한다.
3. 방문 장소의 건물·층 공식 안내도로 바로 연결한다.
4. 사용자가 필요하면 전체 건물과 전체 층을 직접 탐색한다.
5. 공식 지도, 병원 내부 승인 데이터와 시연 데이터를 명확히
   구분한다.
6. 검증되지 않은 창구번호, 대기시간과 이동 경로를 생성하지 않는다.

## 3. 비목표

- 공개 지도만으로 최단 경로를 추정하지 않는다.
- 실시간 실내 위치를 구현하지 않는다.
- 실시간 혼잡도·대기시간을 추정하지 않는다.
- AI가 처리 장소, 의료 준비사항 또는 필요 서류를 생성하지 않는다.
- 모든 업무 종류를 첫 구현에 포함하지 않는다.

제품 정보구조는 `서류 발급`, `수납`, `검사`, `복약` 네 범주를
지원한다. 첫 구현에서는 `서류 발급` 한 범주를 목적 선택부터 공식
층 지도까지 완성한다. 데이터가 준비되지 않은 나머지 범주는
비활성 버튼으로 미리 노출하지 않는다.

## 4. 공식 공개 층 범위

2026-07-30 삼성서울병원 공식 원내 위치 안내에서 노출되는 층
범위는 다음과 같다.

| 건물 | 공개 층 |
|---|---|
| 본관 | B3F, B2F, B1F, 1F~20F |
| 별관 | B3F, B2F, B1F, 1F~8F |
| 암병원 | B3F, B2F, B1F, 1F~11F |
| 양성자치료센터 | B3F, B1F |

층 URL을 규칙으로 추측해 무조건 노출하지 않는다. 초기 데이터
적재 시 각 공식 페이지와 지도 이미지가 실제로 응답하는지 검증하고,
검증된 층만 `PUBLIC` 상태로 제공한다.

## 5. 정보 구조

```text
홈
└─ 이용 안내
   ├─ 목적 기반 바로 연결
   │  ├─ 서류 발급
   │  ├─ 수납
   │  ├─ 검사
   │  └─ 복약
   │     └─ 세부 업무
   │        └─ 공식 처리 방법
   │           └─ 방문 장소
   │              └─ 해당 건물·층 지도
   └─ 전체 건물·층별 안내
      └─ 건물 선택
         └─ 전체 층 선택
            └─ 시설 목록
               └─ 공식 지도에서 확인
```

`전체 건물·층별 안내`는 이용 안내 첫 화면과 목적 결과 화면 양쪽에
항상 노출한다.

## 6. 핵심 사용자 흐름

### 6.1 목적 기반 바로 연결

```text
이용 안내
→ 서류 발급
→ 필요한 서류 선택
→ 온라인·모바일·병원 방문 방법 확인
→ 방문이 필요한 경우 공식 장소 선택
→ 이 장소로 길찾기
→ 목적지 건물·층 공식 지도
→ 현재 위치 선택
→ 검증된 경로가 있으면 단계 안내
→ 경로가 없으면 목적지 시설번호와 공식 지도만 제공
```

방문보다 온라인·모바일 발급이 먼저 가능한 서류는 비대면 방법을
우선 표시한다. 병원 방문을 불필요하게 유도하지 않는다.

### 6.2 전체 건물·층별 안내

```text
전체 건물·층별 안내
→ 본관 / 별관 / 암병원 / 양성자치료센터
→ 지하층을 포함한 전체 공개 층
→ 층별 시설 목록과 검색
→ 시설 선택
→ 공식 지도와 공식 시설번호 확인
→ 검증된 경로가 있으면 길찾기
```

최근 본 층과 목적지 층을 상단에 먼저 보여주되 전체 층 목록을
숨기지 않는다.

## 7. 화면 설계

### S1. 이용 안내 홈

- 상단 제목: `무엇을 하러 가시나요?`
- 목적 검색 입력
- `서류 발급`, `수납`, `검사`, `복약` 큰 분류 버튼
- 현재 환자 일정에서 확인된 다음 방문 장소
- 독립된 `전체 건물·층별 안내` 버튼
- 하단 메뉴: `홈 / 일정 / 이용 안내`

자유 입력은 목적 분류에만 사용한다. 검색 결과가 없으면 장소를
생성하지 않고 전체 층별 안내와 안내 데스크를 제안한다.

### S2. 목적 결과

Caremate 참고 화면에서 다음 표현 구조를 차용한다.

- 처리할 업무 제목
- 이용 가능한 처리 방법
- 방문이 필요한 경우 건물·층·공식 시설명
- 처리 순서
- 준비물
- 큰 `이 장소로 길찾기` 버튼

다음 항목은 병원 시스템에서 값을 받았을 때만 표시한다.

- 창구번호
- 번호표 종류
- 운영시간
- 예상 대기시간

값이 없으면 `병원 확인 필요`로 표시하지 않고 해당 필드 자체를
숨긴다. 필수 정보가 없어 업무 완료가 불가능하면 안내 데스크 문의
상태를 표시한다.

### S3. 전체 건물·층별 안내

- 건물 전환 탭
- 선택한 건물의 전체 공개 층 목록
- 지하층과 지상층의 시각적 구분
- 층별 대표 시설 요약
- 시설명 검색
- 현재 선택한 층의 공식 지도 미리보기
- 공식 원문 링크와 확인일

층 목록은 모바일에서 가로 칩으로 축약하지 않는다. 전체 층을 한눈에
파악할 수 있는 세로 목록 또는 두 열 목록을 사용한다.

### S4. 층 상세

- 건물명·층
- 공식 지도
- 공식 시설번호와 시설명 목록
- 선택 시설 강조
- `여기를 목적지로 설정`
- `현재 위치에서 길찾기`

공개 지도에 좌표 데이터가 없으면 붉은 선을 표시하지 않는다. 시설
번호와 지도 원문을 통해 사용자가 위치를 확인하게 한다.

### S5. 경로 안내

- 목적지 건물·층·시설명
- 사용자가 선택한 현재 위치
- 현재 보고 있는 건물·층
- 병원에서 검증한 통로 좌표가 있을 때만 제공하는 이동선
- 건물·층 변경 단계
- `이전 안내 / 다음 안내`

현재 구현처럼 모든 지도에 공통 좌표를 적용하는 붉은 선은 사용자
화면에서 제거한다. 지도 비율 안에 선이 들어간다는 사실만으로 실제
경로가 되지 않는다. 벽·진료실·통제구역을 가로지르지 않고 실제
통로와 출입구를 따라야 한다.

엘리베이터 또는 에스컬레이터가 필요한 경로는 하나의 긴 선으로
표현하지 않고 다음 세 구간으로 나눈다.

```text
현재 층
→ 현재 위치에서 이용 가능한 수직 이동 수단까지
→ 엘리베이터 또는 에스컬레이터로 층 이동
→ 도착 층 출구에서 목적지까지
```

각 구간의 화면 동작은 다음과 같다.

1. 현재 층 지도에서 이용할 엘리베이터 또는 에스컬레이터 위치를
   강조한다.
2. 검증된 보행 경로가 있으면 현재 위치에서 해당 입구까지만 선을
   표시한다. 선의 마지막 좌표는 지도 안의 실제 이동 수단 아이콘과
   일치해야 한다.
3. `이동 수단에 도착했어요`를 누르면 지도 대신
   `현재 층 → 도착 층` 전환 화면을 표시한다.
4. 도착 층 확인 후 해당 층 공식 지도로 바꾸고, 같은 엘리베이터
   또는 연결된 에스컬레이터 출구를 출발점으로 목적지 구간을
   안내한다.

특정 엘리베이터가 목적 층에 정차하는지 확인되지 않았거나 지도에
엘리베이터 출입구 좌표가 없으면 선을 그리지 않는다. 이 경우 공식
지도에서 엘리베이터 아이콘만 확인하도록 하고 안내 데스크 문의를
함께 제공한다.

에스컬레이터는 층별 입구·출구 쌍, 상행·하행 방향과 운행 상태가
확인된 경우에만 선택지로 제공한다. 현재 층의 선은 에스컬레이터
입구에서 끝나야 하며 지도 경계를 향해 연장하지 않는다. 도착 층의
선은 대응하는 출구 좌표에서 새로 시작한다. 지도 이미지의
`overflow: hidden`으로 잘린 선을 정상 경로로 취급하지 않는다.

경로 상태는 다음 세 가지다.

| 상태 | 화면 동작 |
|---|---|
| `VERIFIED` | 병원 승인 경로와 사용자 표식 제공 |
| `MAP_ONLY` | 공식 지도와 목적지·엘리베이터 시설번호만 제공 |
| `UNAVAILABLE` | 가까운 안내 데스크 문의 |

현재 코드의 공통 수동 polyline은 발표 화면을 포함한 사용자
화면에서 삭제한다. 개발 중 좌표 실험이 필요하면 사용자 UI와
분리된 개발 도구에서만 사용한다.

붉은 이동선을 `VERIFIED`로 제공하려면 다음 조건을 모두 충족해야
한다.

- 출발점과 목적지가 승인된 지도 좌표를 가진다.
- 선의 모든 RouteEdge가 실제 통로 또는 출입구다.
- 선이 벽, 진료실과 통제구역을 통과하지 않는다.
- 엘리베이터 구간의 끝점이 실제 출입구 좌표와 일치한다.
- 해당 엘리베이터의 운행 층과 접근성 정보가 확인됐다.
- 에스컬레이터 구간은 입구·출구 쌍과 상행·하행 방향이 확인됐다.
- 모든 선분과 사용자 표식이 지도 viewBox 내부에서 시작하고 끝난다.
- 적용 중인 MapVersion이 유효하다.
- 현장에서 동일 경로를 걸어 검증했다.

## 8. 데이터 모델

### Building

- `id`
- `name`
- `officialCode`
- `displayOrder`
- `sourceUrl`

### Floor

- `id`
- `buildingId`
- `code`: `B3F`, `1F`, `20F`
- `level`: 지하층은 음수, 지상층은 양수
- `mapImageUrl`
- `sourceUrl`
- `sourceCheckedAt`
- `publicationStatus`

### Place

- `id`
- `floorId`
- `officialNumber`
- `officialName`
- `aliases`
- `mapX`, `mapY`: 병원 승인 좌표가 있을 때만 값 보유
- `sourceStatus`

### Purpose

- `id`
- `category`
- `name`
- `searchTerms`

### ServiceOption

- `id`
- `purposeId`
- `channel`: `ONLINE`, `MOBILE`, `ONSITE`
- `placeId`: 방문일 때만 사용
- `requiredItems`
- `orderedSteps`
- `sourceUrl`
- `approvedAt`

### RouteNode·RouteEdge

- 지도 좌표
- 연결 가능한 노드
- 노드 종류: 통로, 교차점, 출입구, 엘리베이터 입구·출구,
  에스컬레이터 입구·출구
- 이동 수단
- 접근성
- 엘리베이터 운행 층과 엘리베이터 뱅크 식별자
- 에스컬레이터 연결 층, 방향과 운행 상태
- 출입 제한
- 유효 시작·종료일
- 승인 상태

`Place`와 `RouteNode`는 분리한다. 시설의 표시 위치와 실제 이동
가능한 통로 좌표는 같은 정보가 아니다.

### MapVersion

- 건물·층
- 버전
- 유효 기간
- 공사·이전 메모
- 승인자와 승인시각

## 9. 데이터 신뢰도

모든 장소·업무·경로에는 다음 출처 상태를 사용한다.

| 상태 | 의미 | 사용자 제공 |
|---|---|---|
| `HOSPITAL_VERIFIED` | 병원 내부에서 승인 | 운영 기능 제공 |
| `OFFICIAL_PUBLIC` | 삼성서울병원 공개 페이지 확인 | 공식 공개 정보로 표시 |
| `DEMO` | 발표용 수동 데이터 | 발표 모드에서만 표시 |
| `UNKNOWN` | 출처 없음 | 사용자에게 제공하지 않음 |

`3번 키오스크`, 수동 예상시간과 공통 붉은 선은
`OFFICIAL_PUBLIC`으로 취급하지 않는다.

## 10. 외부 자료 사용 원칙

- 삼성서울병원 공식 층별 지도와 시설명을 우선한다.
- Caremate는 화면 배치와 정보의 읽는 순서만 참고한다.
- Caremate의 환자, 창구번호, 대기시간, 처리 절차는 가져오지 않는다.
- 공식 페이지 전체를 복제하지 않고 구조화한 시설 데이터와 원문
  링크를 제공한다.
- 지도 원격 로딩 실패 시 빈 이미지 대신 시설 목록과 원문 링크를
  유지한다.

## 11. 오류와 복구

- 공식 지도 없음: 시설 목록과 원문 링크 제공
- 시설 좌표 없음: 붉은 선 없이 시설번호 강조
- 엘리베이터 좌표·운행 층 없음: 엘리베이터 경로 생성 금지
- 에스컬레이터 입출구·방향 없음: 에스컬레이터 선택지 숨김
- 목적 처리 장소 없음: 안내 데스크 문의
- 복수 장소: 운영시간을 추측하지 않고 사용자가 장소 선택
- 지도 버전 만료: 경로 안내 중단, 최신 확인 필요
- 검색 결과 없음: 전체 건물·층별 안내로 이동

## 12. 접근성

- 주요 버튼 높이 최소 48px
- 지하층을 색상만으로 구분하지 않고 `지하` 텍스트 병기
- 건물·층·시설을 스크린리더 제목 구조로 제공
- 지도 없이도 시설번호와 시설명을 읽을 수 있게 함
- 사용자 표식 애니메이션은 모션 감소 설정에서 정지
- 현재 층과 선택 시설을 텍스트와 `aria-current`로 표시

## 13. 테스트

### 데이터 검증

- 공식 공개 층 범위와 코드 일치
- 모든 공개 층에 source URL 존재
- 공식 시설번호 중복 방지
- 목적 처리 장소가 실제 Place를 참조
- DEMO 경로가 운영 응답에 포함되지 않음
- 모든 엘리베이터 전환이 동일한 엘리베이터 뱅크의 운행 층을 사용
- 모든 에스컬레이터 전환이 승인된 입구·출구 쌍과 방향을 사용

### 모델 테스트

- 목적이 온라인 처리로 먼저 연결되는 경우
- 방문 목적이 특정 건물·층으로 연결되는 경우
- 복수 방문 장소 선택
- MAP_ONLY와 UNAVAILABLE fallback
- 지하층과 고층 정렬
- 보행 구간의 시작·끝이 엘리베이터 출입구 노드와 일치
- 에스컬레이터 구간 전후 선이 지도 안의 입구·출구 노드와 일치
- 벽·통제구역을 통과하는 RouteEdge 거부
- viewBox 경계를 벗어나는 선분과 표식 거부

### UI 테스트

- 이용 안내 첫 화면의 목적 분류
- 전체 건물·전체 층 탐색
- 목적 결과에서 해당 층으로 deep link
- 지도 이미지 실패 상태
- 경로 미검증 시 붉은 선 미표시
- 엘리베이터 안내가 현재 층·층 전환·도착 층으로 분리됨
- 에스컬레이터 안내가 지도 밖으로 잘리지 않고 층별 구간으로 분리됨
- 키보드·스크린리더·모션 감소

### 현장 검증

운영 경로는 삼성서울병원 현장에서 출발점·목적지·층 전환을
직접 걸어 본 뒤 승인한다. 현장 검증 전에는 `VERIFIED` 상태를
부여하지 않는다.

## 14. 구현 단계

### 1단계

- 이용 안내 홈과 `서류 발급` 목적 선택
- 공식 서류 유형·처리 채널·방문 장소 연결
- 전체 건물·공개 층 카탈로그
- 층별 공식 시설 목록
- 전체 건물·층별 안내 UI
- 목적 결과에서 층 상세 deep link
- 현재 공통 수동 붉은 경로를 사용자 화면에서 제거
- 엘리베이터·에스컬레이터 안내를 현재 층·층 전환·도착 층으로
  분리

### 2단계

- 수납·검사·복약 ServiceOption
- 온라인·모바일 우선 안내
- 병원 내부 승인 콘텐츠 관리

### 3단계

- 병원 승인 RouteNode·RouteEdge
- 접근 가능한 경로
- 지도 버전·공사 구간 관리
- 현장 검증 경로만 운영 제공

## 15. 완료 기준

- 네 건물의 공개 전체 층을 탐색할 수 있다.
- 지하층이 누락되지 않는다.
- `서류 발급` 목적 선택 후 공식 장소가 있는 층으로 바로 이동한다.
- 확인되지 않은 `3번 키오스크`, 창구번호와 예상 대기시간을
  노출하지 않는다.
- 병원 승인 경로가 없으면 붉은 이동선을 노출하지 않는다.
- 엘리베이터 경로가 방이나 벽을 가로지르거나 지도 밖에서 끝나는
  화면이 없다.
- 에스컬레이터 경로가 지도 경계에서 잘리거나 실제 입출구와 무관한
  좌표에서 시작·종료하지 않는다.
- 공식 정보와 발표용 데이터를 코드·API·화면에서 구분한다.
