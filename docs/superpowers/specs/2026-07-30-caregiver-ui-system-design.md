# Wait:ON 보호자 UI 시스템 고도화 설계

- 작성일: 2026-07-30
- 상태: 승인
- 참고 화면: `https://caremate-hospital-guide.vercel.app/#/`
- 대상: 보호자용 웹 프로토타입 전체

## 1. 목표

Wait:ON의 보호자 여정과 의료 안전 원칙은 유지하면서, 참고 화면의 장점인
명확한 정보 위계, 모바일 셸, 상태 카드, 날짜 선택 일정, 고정 하단 메뉴를
전체 화면에 일관되게 적용한다.

이번 변경은 참고 서비스의 브랜드나 화면을 복제하는 작업이 아니다.
검증된 시각 패턴을 Wait:ON의 다음 핵심 질문에 맞게 재구성한다.

1. 환자가 지금 어느 단계인가?
2. 보호자가 지금 해야 할 일은 무엇인가?
3. 오늘과 다른 날짜에 어떤 일정이 있는가?
4. 목적 업무는 어디에서 어떤 순서로 처리하는가?
5. 어떤 정보가 병원 확인이고 어떤 정보가 일반 안내인가?

## 2. 선택한 접근

`UI 시스템과 상호작용까지 적용`하는 안을 채택한다.

- 시각 언어만 교체하지 않고 홈, 일정, 치료 진행, 이용 안내의 읽기
  순서와 상호작용을 함께 개선한다.
- 기존 `홈 / 일정 / 이용 안내` 3개 주요 메뉴는 유지한다.
- 진행상황은 별도 하단 메뉴가 아니라 홈의 현재 상태 카드에서 연다.
- 참고 화면의 `진료 메모`와 AI 의료 요약은 현재 MVP에 도입하지 않는다.
- 자유 질문형 AI 입력은 의료 질의가 아니라 병원 이용 목적 검색으로
  제한한다.

## 3. 참고 화면에서 채택하는 요소

### 채택

- 최대 430px의 중앙 모바일 셸
- 짙은 상단 영역과 밝은 본문의 명확한 대비
- 흰 카드, 큰 모서리, 약한 그림자
- 현재 상태를 가장 큰 카드로 표현하는 방식
- 날짜 스트립과 날짜별 일정 카드
- 완료·현재·예정 상태가 구분되는 세로 타임라인
- 검색창과 목적 바로가기를 결합한 이용 가이드
- 화면 전환 중에도 유지되는 고정 하단 메뉴
- 기능별 보조색과 단순한 선형 아이콘

### 그대로 채택하지 않는 요소

- 참고 프로토타입의 날짜는 눌러도 선택 상태와 일정이 실제로 바뀌지
  않았다. Wait:ON에서는 날짜 선택을 실제 상태 전환으로 구현한다.
- 다섯 개 하단 메뉴는 고령 사용자에게 선택 부담이 크므로 세 개로
  유지한다.
- 작은 영문 보조 라벨과 11px 수준의 본문은 확대한다.
- AI가 복약·진단·주의사항을 생성하는 화면은 의료 안전 범위에서 제외한다.
- 참고 서비스의 이름, 로고, 아이콘 자산과 고유 문구는 사용하지 않는다.

## 4. 디자인 토큰

Wait:ON의 기존 녹색 정체성을 유지하고 참고 화면의 네이비 구조를
결합한다.

| 역할 | 값 | 사용 |
| --- | --- | --- |
| `--color-hero` | `#0D1C31` | 상단 히어로, 화면 헤더 |
| `--color-primary` | `#08765C` | 주요 행동, 현재 상태, 선택 메뉴 |
| `--color-primary-soft` | `#E4F4EE` | 선택 배경, 상태 보조 |
| `--color-ai` | `#477EF2` | AI 재구성 콘텐츠에만 사용 |
| `--color-page` | `#E9EDF4` | 데스크톱 바깥 배경 |
| `--color-surface` | `#F7F9FC` | 모바일 앱 배경 |
| `--color-card` | `#FFFFFF` | 카드 |
| `--color-text` | `#13231D` | 본문과 제목 |
| `--color-muted` | `#68766F` | 보조 설명 |
| `--color-warning` | `#B7791F` | 확인 필요와 제한 |
| `--radius-card` | `20px` | 주요 카드 |
| `--shadow-card` | `0 8px 28px rgba(20,40,75,.07)` | 카드 구분 |

타이포그래피는 `Noto Sans KR` 또는 현재 시스템 한글 글꼴을 사용한다.
본문은 최소 16px, 보조 문구는 최소 14px로 유지한다.

## 5. 공통 셸

### 데스크톱

- 페이지 바깥은 `--color-page` 배경이다.
- 앱은 최대 430px, 최소 높이 100dvh의 중앙 셸이다.
- 셸은 `--color-surface` 배경과 약한 그림자를 가진다.

### 모바일

- 720px 이하에서는 전체 너비를 사용하고 셸 테두리와 바깥 그림자를
  제거한다.
- 안전 영역을 고려해 헤더와 하단 메뉴에 패딩을 적용한다.

### 고정 하단 메뉴

순서는 항상 다음과 같다.

1. 홈
2. 일정
3. 이용 안내

선택 메뉴는 색상, 아이콘, 굵기와 `aria-current="page"`를 함께 사용한다.
메뉴 높이는 안전 영역을 제외하고 최소 72px이며, 각 조작 영역은 최소
48px이다. 본문 마지막 내용이 메뉴에 가리지 않도록 하단 여백을 둔다.

## 6. 화면별 설계

### S1. 환자 연결

- 짙은 헤더에 Wait:ON 로고와 `보호자 동행 안내`를 표시한다.
- 환자 정보는 하나의 큰 흰 카드로 묶는다.
- 환자 동의·보호자 인증 원칙은 별도의 신뢰 안내 카드로 분리한다.
- `보호자로 연결하기`를 화면의 유일한 주요 버튼으로 유지한다.

### S2. 보호자 홈

읽기 순서는 다음과 같다.

1. 보호자 인사와 연결 환자
2. 병원 확인 현재 상태
3. 지금 할 보호자 업무
4. 오늘 일정 미리보기
5. 다음 안내와 주의사항

상단 히어로는 짙은 배경을 사용하지만 의료 질문용 AI 입력은 넣지 않는다.
대신 `무엇을 처리하시나요?` 목적 검색을 제공하고 `서류 발급`, `검사실
이동`, `수납` 등의 바로가기를 보여준다.

현재 상태 카드는 흰 배경에 다음 요소를 갖는다.

- `병원 확인` 출처
- 현재 단계명
- 한 문장 상태 설명
- 전체 단계 중 현재 위치
- 진행상황 상세 진입

`지금 할 일`은 상태 카드 아래의 독립 카드로 표시한다. 홈에서 여러 행동을
동시에 강조하지 않고 현재 업무의 주요 행동 하나만 강조한다.

오늘 일정은 최대 세 개만 미리 보여주고 `전체 일정 보기`로 연결한다.

### S3. 환자 일정

상단에는 선택한 날짜 요약 카드와 5일 날짜 스트립을 표시한다.

- 기본 선택은 오늘이다.
- 이전·다음 날짜로 이동할 수 있다.
- `달력 보기`로 기존 월간 달력을 펼치거나 접을 수 있다.
- 일정이 있는 날짜에는 환자 표식 또는 점과 일정 개수를 표시한다.
- 선택 날짜는 색상, 테두리와 `aria-pressed="true"`로 구분한다.
- 날짜 선택 즉시 날짜 제목, 총 일정 수와 일정 목록이 함께 바뀐다.
- 오늘이 아닌 날짜에서는 `오늘로 돌아가기`를 제공한다.

일정 카드는 시간 열과 내용 카드로 나눈다.

- 시간과 완료·예정 상태
- 진료·검사·수납·서류 유형
- 일정명
- 건물·층·장소
- 필요한 경우 준비사항
- 목적지가 있으면 `길찾기` 진입

일정이 없는 날짜에는 `등록된 병원 일정이 없습니다`와 다른 날짜 선택
안내를 표시한다. 다른 날짜의 일정을 임의로 복사하지 않는다.

### S4. 치료 진행 상세

읽기 순서는 기존 안전 원칙을 유지한다.

1. 병원 확인 상태 카드
2. AI 재구성 일반 과정 미디어
3. 일반적인 치료 과정 타임라인
4. 안전 고지
5. 데모 전용 단계 제어

병원 확인 상태는 녹색 또는 네이비 강조 카드로 표시한다. AI 미디어에는
파란색만 사용해 병원 상태와 시각적으로 분리한다.

타임라인은 하나의 흰 카드 안에서 완료·현재·예정을 구분한다.

- 완료: 체크 아이콘과 완료 시각
- 현재: 굵은 테두리, `현재 진행 중`, `aria-current="step"`
- 예정: 회색 번호와 `예정`

예상 종료시각은 표시하지 않는다.

### S5. 목적 기반 이용 안내

상단 짙은 영역에 다음을 배치한다.

- `무엇을 처리하시나요?`
- 목적 검색 입력
- 검색 실행
- 자주 찾는 목적 칩

결과 카드의 읽기 순서는 다음과 같다.

1. 업무 목적
2. 온라인·모바일 우선 처리 가능 여부
3. 방문할 곳
4. 번호표 필요 여부
5. 확인된 준비물
6. 처리 순서
7. 삼성서울병원 공식 출처
8. `이 장소로 안내`

확인되지 않은 창구번호, 번호표와 대기시간을 생성하지 않는다. 검색은
병원 이용 업무만 다루며 의료 판단 질문에는 답하지 않는다.

### S6. 전체 건물·층별 안내와 길찾기

- 본관·별관·암병원·양성자치료센터 탭을 동일한 카드 언어로 표현한다.
- 선택 건물과 층을 상단 고정 선택 영역에 표시한다.
- `MAP_ONLY`, `VERIFIED`, `UNAVAILABLE` 안전 상태는 유지한다.
- 공개 지도에는 추정 경로선을 그리지 않는다.
- 병원 승인 경로가 있을 때만 지도 내부 복도선과 층 전환 화면을 표시한다.
- 엘리베이터·에스컬레이터 선택은 검증된 연결 정보가 있을 때만 제공한다.

### S7. 제한 안내와 의료진 질문

- 경고색 카드는 `먹어도 된다`가 아니라 `지금은 제공하지 마세요`와
  `확인 전에는 제공하지 마세요`를 표시한다.
- 공식 제한, 적용 기간과 출처를 우선한다.
- 질문 목록은 보호자가 의료진에게 물어볼 내용을 정리하는 기능이다.
- AI가 의료 답변이나 복약 지침을 생성하지 않는다.

## 7. 상태와 데이터 흐름

UI 고도화는 기존 API 계약을 바꾸지 않는 것을 기본으로 한다.

```text
CaregiverJourneyResponse
→ 화면 상태 변환
├─ 현재 치료 상태
├─ 보호자 업무
├─ 일정 목록
└─ 공식 이용 안내
→ 선택 상태
├─ 현재 메뉴
├─ 선택 날짜
├─ 선택 건물·층
└─ 데모 단계(sessionStorage)
→ 화면
```

일정의 `selectedDate`는 `Asia/Seoul` 기준 `YYYY-MM-DD` 문자열로 관리한다.
선택 날짜 변경은 서버 데이터를 변경하지 않고 현재 받은 일정 목록을
필터링한다. 일정 추가·수정 기능은 이번 UI 범위에 포함하지 않는다.

## 8. 로딩·빈 상태·오류

- 초기 조회: 카드 골격 화면과 `보호자 정보를 확인하고 있습니다`
- 조회 실패: 현재 입력과 메뉴를 유지하고 `다시 시도`
- 일정 없음: 선택 날짜를 유지한 빈 상태
- 공식 이용 안내 없음: 추측 대신 공식 안내 데스크 문의
- 지도 경로 없음: 공식 위치 지도와 원문 링크만 제공
- AI 미디어 실패: 정지 포스터, 이후 기본 장면 순으로 대체

오류 때문에 하단 메뉴와 이전 화면 이동이 사라지지 않도록 한다.

## 9. 접근성

- 기준 폭 390×844, 추가 검증 320px와 1280×900
- 주요 조작 영역 최소 48px
- 본문 최소 16px, 보조 문구 최소 14px
- 200% 글자 확대에서도 주요 행동과 하단 메뉴가 겹치지 않음
- 색상 외에 텍스트, 아이콘과 상태 문구 사용
- 날짜는 실제 `button` 요소로 구현
- 키보드 방향키 또는 Tab으로 날짜를 이동할 수 있음
- `prefers-reduced-motion`에서 카드·미디어·지도 전환 모션 제거
- 화면마다 하나의 `h1`과 논리적인 `h2` 순서 유지

## 10. 검증 기준

1. 홈에서 10초 안에 현재 상태와 지금 할 일을 말할 수 있다.
2. 일정 화면에서 다른 날짜를 선택하면 날짜 제목과 목록이 함께 바뀐다.
3. 일정이 있는 날짜와 없는 날짜를 색상 없이도 구분할 수 있다.
4. 일정 장소에서 이용 안내 또는 길찾기로 바로 이동한다.
5. 병원 확인 상태와 AI 일반 안내를 서로 다른 정보로 이해한다.
6. 목적 검색 결과에서 공식 출처와 처리 순서를 찾을 수 있다.
7. 390×844에서 가로 스크롤과 하단 메뉴 겹침이 없다.
8. 200% 글자 확대와 키보드만으로 핵심 흐름을 완료한다.
9. 기존 데모 시나리오 전환, AI 미디어와 공식 지도 안전 상태가 유지된다.

## 11. 구현 범위

### 포함

- 전역 디자인 토큰과 모바일 셸
- 공통 헤더, 카드, 버튼, 칩과 하단 메뉴
- 홈 정보 위계 재구성
- 실제 날짜 선택이 동작하는 일정 화면
- 치료 진행 타임라인과 AI 카드 스타일 통합
- 목적 기반 이용 안내 스타일 통합
- 빈 상태, 오류와 반응형 개선
- 컴포넌트·E2E·빌드 검증

### 제외

- 실제 환자 로그인·보호자 인증
- 일정 생성·수정·삭제
