# 암 수술 환자 보호자 여정 프로토타입 설계

## 1. 목적

암 수술 환자의 지정 보호자가 병원에서 겪는 하루를 하나의 폐쇄형 흐름으로 구현한다.

보호자는 다음 네 질문에 한 화면 흐름 안에서 답을 얻는다.

1. 환자는 지금 어디까지 진행됐는가?
2. 보호자는 지금 무엇을 해야 하는가?
3. 그 업무를 어디에서 어떤 순서로 처리하는가?
4. 의료진이 설명한 핵심 내용과 다음 행동은 무엇인가?

프로토타입은 제품 가능성과 정보 구조를 검증한다. 실제 임상 효과, 업무시간 감소 또는 환자 불안 감소를 입증하지 않는다.

## 2. 대표 시나리오

- 환자: 위암 수술을 받는 68세 가상 환자 `김정우`
- 사용자: 환자가 지정한 42세 보호자 `김서연`
- 방문 맥락: 지방에서 방문해 수술 당일 장시간 대기
- 완료 여정:
  - 가상 보호자 연결
  - 수술 진행 확인
  - 일반적인 수술 과정 설명 확인
  - 입원 서류 발급 업무 확인
  - 키오스크 이동 안내
  - 업무 완료
  - 수술 종료·회복실 이동 확인
  - 의료진 확인 가상 요약 확인
  - 가족 공유 화면 확인

## 3. 제품 원칙

### 실제 상태와 교육 콘텐츠를 분리한다

`수술 진행 중`과 같은 실제 진행 영역은 병원 시스템에서 수신했다고 가정한 가상 운영 이벤트만 표시한다.

AI 이미지 또는 애니메이션은 일반적인 과정 설명에만 사용한다. 현재 환자에게 실제로 일어나는 일을 재현한다고 표현하지 않는다.

### 보호자에게 지금 필요한 정보만 우선한다

보호자 홈은 다음 세 영역만 우선 표시한다.

1. 환자의 현재 상태
2. 보호자의 지금 할 일
3. 다음 안내

### 목적 기반 안내는 병원이 등록한 규칙을 사용한다

키오스크, 창구, 번호표, 준비물과 이동 순서는 생성형 AI가 만들지 않는다. 프로토타입에 등록된 병원 가상 업무 규칙을 조회한다.

### 진료 요약은 의료지침을 생성하지 않는다

진료 요약은 의료진이 확인했다고 가정한 가상 샘플을 보여준다. 음성 인식, 진단 추론, 처방 생성 또는 실제 Voice EMR 연동은 구현하지 않는다.

### 모든 데이터는 가상 데이터다

실제 환자정보, 실제 삼성서울병원 공간정보, 실제 EMR·OCS 이벤트와 실제 의료기록을 사용하지 않는다.

## 4. 핵심 화면

### 화면 1. 보호자 연결

- 가상 환자 이름, 수술명과 예정시각 표시
- 보호자에게 공유되는 정보 범위 표시
- `보호자로 연결하기` 실행

### 화면 2. 보호자 홈

- 현재 수술 단계와 병원 확인 시각
- 보호자의 현재 업무
- 다음 상태 변경 안내
- 수술 과정 상세 또는 업무 가이드 진입

### 화면 3. 수술 진행 상세

- `수술실 입실 → 수술 준비 → 수술 진행 중 → 회복실 → 종료` 단계 표시
- 실제 확인 상태와 일반적인 과정 설명을 별도 카드로 표시
- 큰 글씨 전환과 음성 설명 진입점은 후속 접근성 검증 범위로
  두며 4일 프로토타입에는 포함하지 않는다.

### 화면 4. 보호자 할 일

- 입원 서류 발급 목적
- 준비물, 예상 소요시간, 번호표 필요 여부
- `경로 안내 시작` 실행

### 화면 5. 목적 기반 이동 가이드

- 현재 위치와 가상 목적지
- 이동 단계
- 키오스크 처리 순서와 대체 창구
- `업무 완료` 실행

### 화면 6. 의료진 설명 요약

- 수술 종료와 현재 위치
- 의료진 확인 가상 설명
- 보호자와 환자의 다음 행동
- 다음 일정
- 가족 공유 화면

## 5. 상태 모델

### 치료 진행 상태

```text
PREPARING
→ IN_OPERATING_ROOM
→ IN_PROGRESS
→ RECOVERY
→ COMPLETED
```

상태는 임상적 상태가 아니라 보호자에게 공개 가능한 운영 단계다.

### 보호자 업무 상태

```text
AVAILABLE
→ IN_PROGRESS
→ COMPLETED
```

`업무 완료`는 실제 병원 수납·서류 시스템의 완료 판정이 아니라 프로토타입 내부 사용자 행동이다.

### 의료진 설명 상태

```text
UNAVAILABLE
→ CONFIRMED
```

`CONFIRMED`가 되기 전에는 AI가 임시 요약을 표시하지 않는다.

## 6. 시스템 구성

### 웹

`apps/web`에 Next.js App Router 기반 모바일 우선 웹을 추가한다.

- 여정별 화면과 공통 모바일 셸
- API client
- 로딩·오류·빈 상태
- 큰 글씨, 충분한 터치 영역과 명확한 상태 레이블

### 공유 계약

`packages/contracts`에 Zod 기반 보호자 여정 계약을 추가한다.

- 진행 상태 enum
- 보호자 업무
- 목적 기반 가이드
- 의료진 확인 요약
- 전체 보호자 여정 응답

### API

`apps/api/src/caregiver-journey`에 기능을 추가한다.

- 가상 여정 조회
- 가상 보호자 연결
- 보호자 업무 완료
- 발표용 다음 치료 단계 전환
- 메모리 기반 가상 저장소

API는 향후 실제 병원 연동을 교체할 수 있도록 저장소 인터페이스 뒤에 가상 데이터를 둔다.

### 데이터 흐름

```text
보호자 웹
→ NestJS Caregiver Journey API
→ 가상 여정 저장소
→ 진행 상태·현재 업무·가이드·요약 응답
→ 보호자 웹 갱신
```

## 7. 프로토타입 API

```text
GET  /caregiver-journeys/demo
POST /caregiver-journeys/demo/link
POST /caregiver-journeys/demo/tasks/{taskId}/complete
POST /caregiver-journeys/demo/advance
```

`advance`는 발표용 기능이다. 일반 사용자 화면에 노출하지 않고 `?demo=1`에서만 조작할 수 있게 한다.

## 8. 오류와 예외 표시

- API 연결 실패: 마지막 상태를 추측하지 않고 다시 시도 안내
- 상태 시각 누락: `확인 시각 정보 없음` 표시
- 보호자 업무 없음: `현재 처리할 업무가 없습니다` 표시
- 가이드 없음: 임의 경로를 생성하지 않고 안내 데스크 문의 표시
- 요약 미확인: `의료진 설명을 확인 중입니다` 표시
- 공유 실패: 원본 요약 화면을 유지하고 재시도 제공

## 9. 24시간 범위

### 포함

- 가상 환자 1명
- 보호자 1명
- 수술 여정 1개
- 보호자 업무 1개
- 병원 가상 경로 1개
- 의료진 확인 가상 요약 1개
- 모바일 우선 반응형 화면
- 발표용 상태 전환

### 제외

- 실제 인증과 환자 동의
- 실제 환자정보
- PostgreSQL 영속화
- EMR·OCS·Voice EMR 연동
- 실내 위치 측정과 실제 최단경로
- 실제 푸시 알림
- 실제 가족 메시지 전송
- 생성형 AI 의료 요약
- AI 영상 생성 파이프라인
- 여러 환자·보호자·병원 지원

## 10. 검증 기준

1. 보호자가 연결부터 가족 공유 화면까지 중단 없이 이동한다.
2. 홈에서 환자 상태, 보호자 할 일과 다음 안내를 10초 안에 구분할 수 있다.
3. 실제 진행 상태와 일반적인 과정 설명이 시각적으로 구분된다.
4. 키오스크, 번호표와 대체 창구 정보가 한 화면 흐름으로 이어진다.
5. `advance` 후 홈과 진행 상세의 상태가 함께 변경된다.
6. 업무 완료 후 완료 상태가 홈에 반영된다.
7. 의료진 확인 전에는 진료 요약이 노출되지 않는다.
8. 390px 모바일 화면에서 페이지 전체 가로 스크롤이 발생하지 않는다.
9. 키보드만으로 주요 흐름을 사용할 수 있다.
10. 기존 API 테스트, 타입 검사와 빌드가 계속 통과한다.
