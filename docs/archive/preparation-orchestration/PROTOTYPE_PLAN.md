# 4일 발표용 프로토타입 제작 계획

## 1. 목표

한 개의 정적인 화면이 아니라 다음 엔드투엔드 흐름이 실제 DB와 API를 통해 동작하는 프로토타입을 만든다.

```text
의료진 로그인
→ 검사 항목 등록
→ 준비 프로토콜 작성·게시
→ 가상 환자 케이스 생성
→ 환자 작업 수행·도움 요청
→ 의료진 대시보드 반영
```

## 2. 완료 기준

- Vercel URL에서 의료진·환자 화면 접속
- OCI API health check 성공
- Supabase PostgreSQL migration 적용
- 의료진이 `대장내시경` 항목을 검색 또는 등록
- 4단계 준비 프로토콜 게시
- 가상 환자 케이스 생성 시 Case Task 4개 자동 생성
- 환자 작업 완료가 DB에 저장
- 도움 요청이 의료진 예외 목록에 표시
- 프로토콜 v2 게시 후 기존 케이스가 v1 스냅샷 유지
- 가상 데이터 표시와 비의료판단 안내 확인

## 3. MVP 화면

### 의료진

1. 로그인
2. 대시보드
3. 검사·수술 카탈로그
4. 항목 등록
5. 프로토콜 편집·미리보기·게시
6. 가상 환자 케이스 생성
7. 환자 케이스 상세

### 환자

1. 현재 할 일
2. 전체 준비 일정
3. 도움 요청

## 4. 데모 콘텐츠

### 카탈로그

- 대장내시경
- 조영 복부 CT
- 뇌 MRI/MRA
- 대장암 수술
- 일반 X-ray

### 완성 프로토콜

대장내시경 하나만 처음부터 끝까지 완성한다.

단계 예시:

1. 검사 3일 전 음식 제한 확인
2. 전날 저녁 식사 확인
3. 장정결제 복용 확인
4. 검사 당일 도착 준비

문구는 `Demo Hospital 가상 지침`으로 명시하며 실제 의료지침으로 사용하지 않는다.

## 5. 하지 않을 일

- 5개 Procedure의 프로토콜을 모두 완성하지 않는다.
- 실제 병원 앱 디자인을 복제하지 않는다.
- 실제 의료진 또는 환자 계정을 연동하지 않는다.
- 실제 문자나 카카오 알림을 보내지 않는다.
- EMR·OCS를 흉내 낸 복잡한 연동 서버를 만들지 않는다.
- AI 챗봇을 넣지 않는다.
- 통계 대시보드를 추가하지 않는다.

## 6. 일정

### 1일차: 토대와 계약

- 모노레포 생성
- Next.js, NestJS 초기 구성
- Supabase 프로젝트·로컬 migration 구성
- 핵심 테이블 migration
- 공통 API 응답과 인증 guard
- 디자인 토큰과 기본 레이아웃
- seed 데이터

완료 조건:

- Web과 API 로컬 실행
- API가 DB 연결
- `/health/ready` 성공
- 로그인 후 `/me` 성공

### 2일차: 카탈로그와 프로토콜

- Procedure 검색·등록 API/UI
- 프로토콜 초안·단계 CRUD
- 게시 트랜잭션
- 환자 미리보기
- 감사 로그 기록

완료 조건:

- UI에서 대장내시경 등록
- 4단계 프로토콜 게시
- 게시 프로토콜 수정 차단

### 3일차: 환자 케이스와 대시보드

- 가상 환자 케이스 생성
- Case Task 스냅샷
- 환자 현재 작업 화면
- 완료·도움 요청
- 예외 대시보드

완료 조건:

- 환자 행동이 의료진 화면에 반영
- 기존 케이스 버전 고정 검증

### 4일차: 배포·QA·발표

- Vercel 배포
- OCI API 배포
- Supabase production-demo migration
- 접근성·모바일 QA
- 데모 데이터 초기화 절차
- 발표 시나리오 리허설
- 장애 시 녹화본과 스크린샷 준비

완료 조건:

- 새 환경에서 데모 2회 연속 성공
- 핵심 자동 테스트 통과
- 발표자 외 팀원이 복구 절차 수행 가능

## 7. 발표 흐름

1. 공개된 병원 지침이 여러 부서와 검사별로 흩어져 있고 조건이 다름을 설명
2. 의료진 화면에서 대장내시경을 등록
3. 병원 승인 프로토콜을 단계별로 작성·게시
4. 68세 가상 환자에게 검사 일정을 등록
5. 환자 모바일 화면에서 현재 할 일을 완료
6. 장정결제 단계에서 도움 요청
7. 의료진 화면에 예외 환자가 즉시 올라오는 과정 시연
8. 새 버전을 게시해도 기존 환자의 안내가 바뀌지 않음을 설명
9. 향후 EMR·OCS 연동 구조 제시
