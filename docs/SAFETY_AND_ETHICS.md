# Wait:ON 안전 및 윤리 기준

## 문서 정보

- 상위 문서: [`PROJECT_V2.md`](./PROJECT_V2.md)
- 게임 규칙: [`GAMEPLAY.md`](./GAMEPLAY.md)
- 문서 목적: 의료 오인, 불안 자극, 개인정보, 중독적 설계와 환자 경험 왜곡을 방지한다.

---

## 1. 기본 입장

Wait:ON은 의료서비스나 의료 판단 도구가 아니다. 병원 대기 중 사용하는 가상의 운영 시뮬레이션이며, 실제 병원의 복잡한 운영을 의도적으로 단순화한다.

게임의 목적은 병원의 사정을 이해시키거나 환자의 불편을 정당화하는 것이 아니다. 사용자가 제한된 자원과 안내의 중요성을 체험하면서 대기 중 짧은 몰입을 얻도록 하는 것이다.

---

## 2. 실제 의료와의 경계

### 하지 않는 것

- 증상 입력
- 진단
- 치료 권고
- 실제 진료 우선순위 결정
- 실제 대기시간 예측
- 실제 수술 진행상황 표시
- 실제 환자 데이터 수집
- 실제 병원 시스템과의 암묵적 연결

### 게임 안의 응급 이벤트

- 실제 응급도 분류 체계를 모사하지 않는다.
- 증상 목록으로 우선순위를 맞히게 하지 않는다.
- 필요한 가상 자원을 제한시간 안에 확보하는 문제가 아니다.
- 선택을 읽는 동안 게임 시간이 멈춘다.
- 결과는 일정, 대기와 운영 위험으로만 표현한다.

---

## 3. 필수 고지

### 시작 화면

> 이 게임의 환자, 병원과 사건은 모두 가상입니다. 실제 진료 순서나 의료 판단과 다르게 단순화되어 있습니다.

### 플레이 화면의 안전 안내

> 현재 몸 상태에 문제가 있으면 게임을 멈추고 현장 의료진에게 알려주세요.

### 응급 이벤트

> 이 상황은 운영 게임을 위해 단순화된 가상 사건이며 실제 의료 판단을 나타내지 않습니다.

### 결과 화면

> 게임 점수는 실제 병원의 운영 품질이나 의료진의 능력을 평가하지 않습니다.

고지는 읽을 수 있는 크기와 대비로 표시하며 약관 안에 숨기지 않는다.

---

## 4. 환자 표현

### 허용

- 대기와 정보 부족에서 오는 답답함
- 병실 선호
- 진행 단계와 예상시간 문의
- 가상 환자마다 다른 안내 필요도
- 안내를 받은 뒤 불확실성이 줄어드는 표현

### 금지

- 환자를 방해물, 적 또는 비용으로 표현
- 불만을 비이성적이거나 우스운 행동으로 묘사
- 통증과 공포를 점수 획득 기회로 사용
- 질환, 장애, 연령, 성별 또는 경제 상황을 성격과 고정 연결
- 환자가 의료진의 어려움을 이해해야 한다는 훈계

---

## 5. 의료진 표현

- 의료진 피로는 개인의 성실성 문제가 아니라 운영 시스템의 제약이다.
- 의료진을 무능하거나 게으른 캐릭터로 표현하지 않는다.
- 특정 직군을 단순 보조 인력처럼 취급하지 않는다.
- 휴식은 비효율이나 처벌이 아니라 환자 안전을 위한 운영 선택이다.
- 게임 점수를 실제 의료진의 능력 평가처럼 설명하지 않는다.

---

## 6. 실패와 위험 표현

### 허용되는 결과

- 대기 증가
- 일정 지연
- 안내 정확도 하락
- 의료진 피로
- 병상 부족
- 운영 위험 증가

### 금지되는 결과

- 사망
- 수술 실패
- 치료 실패
- 심각한 상태 악화
- 실제 의료 사고
- 환자 또는 의료진을 비난하는 실패 화면

환자 안전은 높은 보상을 얻기 위한 베팅 대상으로 사용하지 않는다.

---

## 7. 병실과 병상

- 1인실, 2인실과 6인실은 수용량과 가상 선호의 차이로만 표현한다.
- 병실을 수익 등급으로 만들지 않는다.
- 실제 비용, 보험, 질환, 감염 관리와 성별 배정 규칙을 사용하지 않는다.
- 다른 병실 제안은 환자의 수용 여부가 포함된 가상 선택으로 표현한다.
- 병상 부족을 환자의 탓으로 표현하지 않는다.

---

## 8. 책임 있는 몰입

Wait:ON은 사용자가 진료 호출을 놓칠 만큼 게임을 우선하게 만들어서는 안 된다.

### 사용하지 않는 장치

- 출석 보상
- 연속 접속 보상
- 종료 시 손실
- 에너지 충전
- 기간 한정 보상
- 놓치면 손해 보는 푸시 알림
- 무작위 유료 보상
- 광고 시청 강제
- 읽기 또는 선택 제한시간

### 제공하는 장치

- 모든 화면의 일시정지와 잠시 나가기
- 상태 변경 직후 자동 저장
- 백그라운드 진입 시 자동 일시정지
- 복귀 후 명시적인 계속하기
- 짧은 행동 단위
- 자연스러운 회복 구간

---

## 9. 무작위와 난이도

- 발표와 첫 테스트는 고정 시나리오를 사용한다.
- 반복 플레이는 제약 기반 셔플백으로 반복과 불운을 제한한다.
- 잘한 사용자를 몰래 처벌하는 사건을 만들지 않는다.
- 낮은 성과에서는 복구 도구를 제공하되 이미 결정된 결과를 사후 조작하지 않는다.
- 난이도 상승은 사용자가 선택한다.
- 실제 사용자 건강, 감정 또는 의료 상황을 추측해 난이도를 바꾸지 않는다.

---

## 10. 데이터와 개인정보

### 수집하지 않는 정보

- 이름
- 생년월일
- 연락처
- 환자번호
- 진단명
- 증상
- 검사 결과
- 실제 예약과 진료 일정
- 실제 병실

### MVP 저장 정보

- 가상 게임 상태
- 익명 로컬 설정
- 튜토리얼 진행
- 플레이테스트에 동의한 경우 가상 행동 로그

MVP 저장은 사용자 기기 안에서 이루어진다. 행동 로그를 외부로 전송하는 기능은 별도 동의와 개인정보 검토 전에는 구현하지 않는다.

---

## 11. 생성형 AI

MVP에는 생성형 AI를 사용하지 않는다.

후속 버전에서 가상 이벤트 문구 생성에 사용하더라도 다음을 적용한다.

- 사전 승인된 템플릿 안에서만 생성
- 의료 판단과 실제 병원 정보 입력 금지
- 금지 표현 필터
- 실패 시 규칙 기반 문구 사용
- 모든 생성 결과가 가상임을 표시
- 의료 전문가와 환자 경험 담당자의 검수

---

## 12. 콘텐츠 검수 체크리스트

각 환자, 이벤트와 결과 문구는 다음 질문을 통과해야 한다.

1. 실제 의료 조언처럼 읽히지 않는가?
2. 실제 진료 순서를 학습시키고 있지 않은가?
3. 환자나 보호자를 문제의 원인으로 묘사하지 않는가?
4. 의료진 개인을 비난하지 않는가?
5. 병원 지연을 정당화하거나 훈계하지 않는가?
6. 사망, 실패와 고통을 보상 연출로 사용하지 않는가?
7. 개인정보 입력을 유도하지 않는가?
8. 선택하지 않거나 종료해도 손실이 없는가?
9. 색상과 소리 없이 의미를 이해할 수 있는가?
10. 가상 상황이라는 고지가 필요한 위치에 있는가?

하나라도 통과하지 못하면 콘텐츠를 출시하지 않는다.

---

## 13. 검토 단계

1. 게임 기획 검토
2. 환자 경험 관점 검토
3. 의료 운영 관점 검토
4. 접근성 검토
5. 실제 사용자 플레이테스트
6. 문구와 시각 표현 최종 검수

실제 병원 환경에서 테스트할 경우 병원 운영과 진료 호출을 방해하지 않는 별도 승인 절차를 거친다.
