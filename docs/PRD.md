# Wait:ON 보호자 동행 프로토타입 PRD

## 1. 목표

4일 발표에서 위암 수술 보호자 여정과 건강검진 오전 대장내시경 준비
여정을 전환하며 중단 없이 시연한다.

```text
가상 환자 연결
→ 치료 상태 확인
→ 보호자 업무 수행
→ 환자 일정 확인
→ 이용 목적 선택
→ 공식 층별 안내도 기반 이동
```

```text
가상 건강검진 환자 연결
→ 현재 검사 준비 단계 확인
→ 공식 제한 목록·출처 확인
→ 음식·행동 검색
→ 확인 필요 질문 저장·완료·삭제
```

## 2. 릴리스 범위

### 포함

- 가상 환자·보호자 연결
- 병원 확인 치료 단계 5단계
- 일반적인 수술 과정 교육 화면
- 단계별로 선택 제공되는 AI 재구성 교육 미디어와 정지 포스터·기본 장면 대체
- 보호자 업무와 공식 처리 방법 연결
- 서류 발급의 온라인·모바일·병원 방문 선택지
- `홈 / 일정 / 이용 안내` 하단 메뉴
- 한 환자의 월간 일정과 날짜별 상세
- 본관·별관·암병원·양성자치료센터의 전체 공개 층 안내
- 공식 시설번호·시설명 검색과 원문 연결
- 공개자료 전용 `MAP_ONLY` 안전 화면
- 병원 승인 경로의 층별 선·이동 수단 전환 구조와 단위 테스트
- 발표자 전용 단계 전환
- 모바일 우선 반응형 화면
- 메모리 기반 NestJS API와 Zod 응답 검증
- 건강검진 오전 대장내시경 준비 3단계와 공식 제한 검색
- 의료진 확인 질문 저장·완료·삭제

### 제외

- 실제 로그인·환자 동의·보호자 인증
- 실제 환자정보와 병원 시스템 연동
- 자동 실내 위치, 혼잡도와 경로 이탈 추적
- 병원 승인 2D 공간 그래프와 실제 길찾기 경로
- 예상 치료 종료시각
- 실제 EMR·OCS·Voice EMR
- AI 진단·의료지침 생성·자동 요약
- 실제 메시지·푸시
- PostgreSQL 저장과 운영 배포
- 기존 준비 누락 방지 관리자·의료진 화면

- 보호자: 김서연, 딸

## 4. 기능 요구사항

### FR-LINK 환자 연결

- `GET /caregiver-journeys/demo`에서 가상 여정을 조회한다.
- 연결 전에는 환자, 치료명, 보호자 관계와 데이터 경계를 보여준다.
- `POST /caregiver-journeys/demo/link` 성공 응답을 받은 뒤 홈으로 이동한다.
- 화면에서 연결 상태를 먼저 바꾸지 않는다.

### FR-STATUS 치료 진행

- 상태는 `PREPARING`, `IN_OPERATING_ROOM`, `IN_PROGRESS`, `RECOVERY`, `COMPLETED` 순서다.
- 홈은 현재 상태, 마지막 확인 주체, 다음 안내를 우선 표시한다.
- 일반 수술 과정은 “이해를 돕는 안내”로 별도 표시한다.
- 치료 진행 상세는 병원 확인 상태 다음에 선택 제공되는 AI 재구성 교육
  미디어를 표시하고, 그 아래에 일반 수술 과정 타임라인을 표시한다.
- AI 미디어는 병원이 제공한 치료 상태를 설명할 뿐 상태를 변경·예측하거나
  병원 확인을 대신 검증하지 않는다.
- 미디어를 표시할 수 없어도 정지 포스터 또는 단계별 기본 장면과 텍스트로
  현재 치료 단계와 일반 과정을 확인할 수 있어야 한다.
- 현재 단계에는 텍스트와 `aria-current="step"`을 함께 사용한다.
- 예상 종료시각을 제공하지 않는다.

### FR-TASK 보호자 업무

- 홈에서 현재 업무의 이름과 상태를 확인한다.
- 상세 화면에서 현재 등록된 준비물과 공식 확인 필요성을 표시한다.
- 확인되지 않은 예상시간, 번호표와 창구번호를 표시하지 않는다.
- `공식 처리 방법 확인`으로 목적 기반 가이드에 연결한다.

### FR-GUIDE 목적 기반 이용 가이드

- 업무 목적에서 공식 처리 방법 검색을 시작한다.
- 서류 발급은 온라인·모바일·병원 방문 방법을 구분한다.
- 준비물, 순서, 공식 방문 장소와 출처 원문을 표시한다.
- 방문 장소 선택 시 해당 건물·층·시설을 바로 연다.

### FR-TABS 주요 메뉴

- 환자 연결 후 `홈 / 일정 / 이용 안내`를 항상 동일한 순서로 제공한다.
- 현재 메뉴에는 `aria-current="page"`를 제공한다.

### FR-SCHEDULE 환자 일정

- 서버가 반환한 일정을 `Asia/Seoul` 날짜 기준으로 표시한다.
- 일정 날짜에는 환자 표식과 일정 개수를 표시한다.
- 선택 날짜의 시간, 이름, 건물·층·장소와 준비사항을 표시한다.
- 빈 날짜에는 등록 일정이 없다는 명시적 상태를 표시한다.

### FR-INDOOR 실내 길찾기

- 공개 층별 안내 이미지는 위치 확인용으로만 사용한다.
- `MAP_ONLY`에서는 경로선과 사용자 애니메이션을 표시하지 않는다.
- `VERIFIED`는 병원 승인 2D 지도와 복도·승강기 노드가 있는 경우만
  허용한다.
- 현재 층 선은 이동 수단 입구에서 끝내고 층 전환을 별도 화면으로
  표시한 뒤 도착 층 출구에서 새 선을 시작한다.
- 경로가 없으면 안내 데스크 문의 문구를 표시한다.

### FR-DEMO 발표자 도구

- 홈의 발표자 도구는 `?demo=1`에서만 가상 시나리오 선택을 제공한다.
- 위암 수술 치료 진행 화면은 `?demo=1`에서만 이전·다음·8초 자동 진행
  제어를 제공한다.
- 수술 데모 단계는 브라우저 `sessionStorage`에만 저장하며 실제 병원
  상태 API를 호출하거나 변경하지 않는다.
- 데모 단계가 적용된 상태 출처는 `발표용 병원 상태 시연`으로 표시한다.
- 일반 URL에서는 치료 단계 제어를 렌더링하지 않고 서버 응답을 상태
  원본으로 사용한다.

## 5. 상태와 API

| Method | Path | 목적 |
|---|---|---|
| GET | `/caregiver-journeys/demo` | 현재 가상 여정 조회 |
| POST | `/caregiver-journeys/demo/link` | 가상 보호자 연결 |
| POST | `/caregiver-journeys/demo/tasks/:taskId/complete` | 보호자 업무 완료 |
| POST | `/caregiver-journeys/demo/advance` | 발표용 치료 단계 전환 |

모든 성공 응답은 공유 `CaregiverJourneyResponseSchema`로 검증한다. 비정상 응답은 화면 상태로 사용하지 않는다.

## 6. 비기능 요구사항

### 접근성

- 모든 주요 버튼은 최소 높이 44px이다.
- 키보드 포커스를 명확히 표시한다.
- 상태를 색상만으로 전달하지 않는다.
- 화면 제목과 영역 제목을 의미 순서대로 사용한다.
- 720px 이하에서 단일 열 전체 화면으로 전환한다.
- 모션 감소 설정을 존중한다.

### 신뢰성

- 로딩, 실패, 재시도 상태를 제공한다.
- 변경 후 서버가 반환한 여정을 단일 상태 원본으로 사용한다.
- 업무 식별자는 URL 인코딩한다.
- API 응답이 계약과 다르면 UI에 전달하지 않는다.

### 안전

치료 단계와 일정은 가상 데이터다. 지도 배경과 시설명은
삼성서울병원 공식 공개 안내이며, 공개자료 상태에서는 경로선을
표시하지 않는다.

## 9. 오전 대장내시경 제한 안내

### 가상 시나리오

- 환자: 박영희, 67세
- 보호자: 이민수, 아들
- 검사: 건강검진 오전 9시 대장내시경
- 시작 단계: 검사 3일 전
- 단계: `THREE_DAYS_BEFORE` → `DAY_BEFORE` →
  `ABSOLUTE_FASTING`
- 공식 근거: 삼성서울병원 오전 대장내시경 준비 안내

### FR-SCENARIO-001 발표 시나리오 선택

- 기본 발표 시나리오는 기존 위암 수술 여정이다.
- 발표자 도구에서 오전 대장내시경 여정을 선택할 수 있다.
- 시나리오 선택 결과는 서버가 반환한 가상 여정을 화면 원본으로
  사용한다.
- 대장내시경 여정은 기존 수술 진행 상세를 노출하지 않는다.

### FR-RESTRICTION-001 현재 제한 목록

- 보호자 홈은 현재 단계, 핵심 제한 문구와 적용 기간을 표시한다.
- 상세 화면은 현재 단계에 적용되는 공식 규칙만 표시한다.
- 각 규칙은 대상, 이유, 적용 기간과 공식 출처를 가진다.
- 검사 전날은 오후 7시 전 흰죽 식사, 자정 이후 금식 맥락을
  안내하며 장 정결제 복용을 막는 절대 금식으로 표현하지 않는다.
- 절대 금식 단계는 검사 당일 오전 5시부터 검사 종료 전까지다.
- 가능한 음식 목록이나 섭취 허용 판정은 제공하지 않는다.

### FR-RESTRICTION-002 음식·행동 검색

- 검색은 현재 단계의 대표 항목과 별칭만 일치시킨다.
- 검색어는 공백 제거 후 1자 이상 80자 이하의 단일 문자열이다.
- 명시적 제한은 `DO_NOT_PROVIDE`로 반환한다.
- 일치하는 공식 규칙이 없으면 `CHECK_BEFORE_PROVIDING`으로
  반환한다.
- 어떤 입력에도 허가 또는 안전 판정을 반환하지 않는다.

### FR-QUESTION-001 상담 질문 저장

- 보호자는 검색어를 자동 생성된 질문으로 저장할 수 있다.
- 같은 정규화 검색어의 열린 질문은 한 개만 유지한다.
- 보호자는 질문을 확인 완료로 바꿀 수 있다.
- 보호자는 열린 질문과 완료된 질문을 삭제할 수 있다.
- 질문은 의료진에게 자동 전송되지 않으며 자유서술 답변을 저장하지
  않는다.

### FR-RESTRICTION-DEMO-001 준비 단계 전환

- `?demo=1`에서만 제한 상세 화면에 다음 준비 단계 버튼을 표시한다.
- 단계 전환은 서버 응답 후 화면에 반영한다.
- `ABSOLUTE_FASTING` 이후에는 같은 단계를 유지한다.

### 인수 조건

- 검사 3일 전 `딸기` 검색은 씨 있는 과일 제한을 반환한다.
- 공식 규칙이 없는 `커피` 검색은 확인 필요를 반환한다.
- 절대 금식 단계의 `물` 검색은 제공 금지를 반환한다.
- 절대 금식 단계의 적용 시각은 검사 당일 오전 5시부터다.
- 검색, 질문 저장과 화면 문구에 섭취 허가 결과가 없다.

## 10. 구현 범위: 현 위치 기반 원내 길찾기

삼성서울병원 공개 원내 위치안내는 건물·층·주요 시설과 연결통로를
확인하는 근거로 사용할 수 있지만, 공개 안내도만으로 휴대폰의 실내
현 위치를 자동 판별할 수는 없다.

### 1단계 프로토타입

- 오늘 일정 또는 보호자 업무에서 목적 검사실·창구를 선택한다.
- 사용자가 현재 건물, 층과 가까운 랜드마크를 직접 선택한다.
- 출발지와 목적지를 층별 안내도 위에 표시한다.
- 같은 층은 경로선을, 층·건물 이동은 엘리베이터·연결통로 단위의
  단계 목록을 함께 제공한다.
- 휠체어·유모차 이용자는 계단을 제외한 접근 가능한 경로를 선택한다.
- 공식 이미지는 병원 HTTPS 원본 URL을 배경으로 사용하고 앱의 붉은
  경로를 별도 SVG 계층으로 표시한다.

### 제품화 조건

- 병원이 제공하는 최신 공간·시설·연결통로 데이터
- 공사·폐쇄·이전 정보를 즉시 반영하는 지도 버전과 유효기간
- BLE 비콘, Wi-Fi, QR·NFC 체크포인트 등 실내 위치 기준
- 직원 전용·통제구역을 제외하는 경로 정책
- 경로 이탈, 엘리베이터 운행 중단과 접근성 우회 안내

삼성서울병원 모바일 앱에는 일정에서 채혈 장소를 선택하고
`위치확인`으로 위치를 확인하는 기능이 이미 안내되어 있다. 따라서
Wait:ON의 차별점은 단순 목적지 표시가 아니라 보호자 업무와 연결된
출발지-목적지 경로, 건물·층 전환, 접근성 경로와 최신 운영 변경
반영으로 정의한다.
