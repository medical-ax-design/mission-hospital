# Wait:ON 보호자 동행 프로토타입 PRD

## 1. 목표

4일 발표에서 하나의 암 수술 보호자 여정을 중단 없이 시연한다.

```text
가상 환자 연결
→ 치료 상태 확인
→ 보호자 업무 수행
→ 목적 기반 이동
→ 의료진 확인 설명 공유
```

## 2. 릴리스 범위

### 포함

- 가상 환자·보호자 연결
- 병원 확인 치료 단계 5단계
- 일반적인 수술 과정 교육 화면
- 보호자 업무, 준비물, 예상 소요시간
- 번호표 필요 여부와 가상 목적 기반 이동 순서
- 업무 완료 상태 반영
- 의료진 설명 확인 전·후 게이트
- 가족 공유 미리보기
- 발표자 전용 단계 전환
- 모바일 우선 반응형 화면
- 메모리 기반 NestJS API와 Zod 응답 검증

### 제외

- 실제 로그인·환자 동의·보호자 인증
- 실제 환자정보와 병원 시스템 연동
- 실제 병원 실내지도·혼잡도·위치 추적
- 예상 치료 종료시각
- 실제 EMR·OCS·Voice EMR
- AI 진단·의료지침 생성·자동 요약
- 실제 메시지·푸시·가족 공유
- PostgreSQL 저장과 운영 배포
- 기존 준비 누락 방지 관리자·의료진 화면

## 3. 가상 시나리오

- 환자: 김정우, 68세
- 보호자: 김서연, 딸
- 치료: 위암 수술
- 현재 단계: 수술 준비 중
- 보호자 업무: 입원 서류 발급
- 현재 위치: 수술 대기실
- 목적지: 본관 1층 3번 키오스크
- 준비물: 보호자 신분증

화면에는 실제 데이터처럼 보이지 않도록 발표용 가상 정보임을 표시한다.

## 4. 기능 요구사항

### FR-LINK 환자 연결

- `GET /caregiver-journeys/demo`에서 가상 여정을 조회한다.
- 연결 전에는 환자, 치료명, 보호자 관계와 데이터 경계를 보여준다.
- `POST /caregiver-journeys/demo/link` 성공 응답을 받은 뒤 홈으로 이동한다.
- 화면에서 연결 상태를 먼저 바꾸지 않는다.

### FR-STATUS 치료 진행

- 상태는 `PREPARING`, `IN_OPERATING_ROOM`, `IN_PROGRESS`, `RECOVERY`, `COMPLETED` 순서다.
- 홈은 현재 상태, 마지막 확인 주체, 다음 안내를 우선 표시한다.
- 일반 수술 과정은 “이해를 돕는 안내”로 별도 표시한다.
- 현재 단계에는 텍스트와 `aria-current="step"`을 함께 사용한다.
- 예상 종료시각을 제공하지 않는다.

### FR-TASK 보호자 업무

- 홈에서 현재 업무의 이름, 상태, 예상 소요시간을 확인한다.
- 상세 화면에서 준비물, 처리 장소, 현재 위치와 번호표 필요 여부를 확인한다.
- 완료된 업무는 홈에서 `완료`와 `업무를 완료했습니다`로 표시한다.

### FR-GUIDE 목적 기반 이용 가이드

- 업무 목적에서 경로 안내를 시작한다.
- 목적지, 예상 이동시간, 번호표 필요 여부, 순서, 실패 시 대안을 표시한다.
- 경로는 순서가 있는 목록으로 제공한다.
- 지도 시각물은 실제 지도가 아닌 가상 도식임을 화면에 명시한다.
- 경로가 없으면 안내 데스크 문의 문구를 표시한다.

### FR-SUMMARY 의료진 확인 설명

- `UNAVAILABLE`에서는 `의료진 설명을 확인 중입니다`만 표시한다.
- 확인 전에는 AI나 클라이언트가 설명을 생성하지 않는다.
- `CONFIRMED`에서만 현재 상태, 핵심 내용, 다음 일정을 표시한다.
- 가족 공유는 로컬 미리보기만 열고 외부 API를 호출하지 않는다.

### FR-DEMO 발표자 도구

- `?demo=1`에서만 `다음 단계로 전환`을 표시한다.
- `POST /caregiver-journeys/demo/advance` 응답으로만 단계를 갱신한다.
- `RECOVERY` 이후 가상 의료진 확인 요약을 제공한다.
- 일반 URL에서는 발표자 도구가 노출되지 않는다.

## 5. 상태와 API

| Method | Path | 목적 |
|---|---|---|
| GET | `/caregiver-journeys/demo` | 현재 가상 여정 조회 |
| POST | `/caregiver-journeys/demo/link` | 가상 보호자 연결 |
| POST | `/caregiver-journeys/demo/tasks/:taskId/complete` | 보호자 업무 완료 |
| POST | `/caregiver-journeys/demo/advance` | 발표용 치료 단계 전환 |

모든 성공 응답은 공유 `CaregiverJourneyResponseSchema`로 검증한다. 비정상 응답은 화면 상태로 사용하지 않는다.

## 6. 비기능 요구사항

### 접근성

- 모든 주요 버튼은 최소 높이 44px이다.
- 키보드 포커스를 명확히 표시한다.
- 상태를 색상만으로 전달하지 않는다.
- 화면 제목과 영역 제목을 의미 순서대로 사용한다.
- 720px 이하에서 단일 열 전체 화면으로 전환한다.
- 모션 감소 설정을 존중한다.

### 신뢰성

- 로딩, 실패, 재시도 상태를 제공한다.
- 변경 후 서버가 반환한 여정을 단일 상태 원본으로 사용한다.
- 업무 식별자는 URL 인코딩한다.
- API 응답이 계약과 다르면 UI에 전달하지 않는다.

### 안전

이 프로토타입의 치료 단계, 이동 경로와 의료진 설명은 모두 가상 데이터이며 실제 환자 상태 또는 의료지침이 아니다.

## 7. 완료 기준

- 컴포넌트와 API E2E 테스트가 통과한다.
- TypeScript 오류 없이 NestJS와 Next.js 프로덕션 빌드가 완료된다.
- 390×844와 1280×900에서 주요 흐름을 완료한다.
- 페이지 수준 가로 스크롤과 브라우저 콘솔 오류가 없다.
- 새 사용자가 3분 이내에 전체 발표 여정을 수행한다.

## 8. 후속 제품화 조건

- 병원과 치료·행정 상태 소유권 정의

- 병원 승인 콘텐츠 관리와 변경 이력
- 실제 목적지·키오스크·번호표 규칙 데이터 모델
- EMR·OCS 연동 가능 범위와 법무·보안 검토
- 고령 사용자와 암 환자 보호자 사용성 검증
- 운영 지표 기준선 수집
