## 1. 검증 질문

1. 사용자는 3분 안에 핵심 행동을 이해하는가?
2. 한 번의 선택이 여러 부서에 미치는 영향을 이해하는가?
3. 현재 병목과 그 원인을 찾을 수 있는가?
4. 긴장과 회복의 페이스가 지루하거나 피곤하지 않은가?
5. 갑자기 중단해도 불편하지 않은가?
6. 재접속 후 마지막 상태를 이해하고 이어갈 수 있는가?
7. 플레이 후 대기 발생 구조와 안내의 중요성을 설명하는가?
8. 병원의 지연을 정당화한다고 느끼지 않는가?
9. 실제 의료 판단으로 오해하지 않는가?

## 2. 테스트 단계

### 1단계: 닫힌 루프 테스트

범위:

- 외래와 검사실
- 환자 3명
- 의료진 재배치 1회
- 대기시간과 만족도

목표:

- 행동 → 결과 → 다음 판단 루프가 닫히는지 확인
- 지표 변화의 원인을 설명할 수 있는지 확인

### 2단계: UX 테스트

범위:

- 병원 전체 화면
- 부서 확대
- 이벤트 선택
- 병상 현황
- 잠시 나가기

목표:

- 병목 탐색 시간
- 핵심 행동 도달 단계
- 정보 과부하
- 카메라와 모션 불편

### 3단계: 하루 페이싱 테스트

범위:

- 9분 병원 하루
- 이벤트 6개
- 전개·정점·회복
- 하루 결과

목표:

- 긴장과 회복의 균형
- 이벤트 반복감
- 회복 가능성
- 재도전 의향

### 4단계: 중단·복귀 테스트

범위:

- 행동 직후 종료
- 이벤트 선택 중 종료
- 백그라운드 전환
- 저장 실패 모의

목표:

- 진행 손실
- 복귀 위치 이해
- 자동 진행 오해

## 3. 참가자

### 첫 사용성 테스트

- 최소 5명
- 모바일 게임 경험이 서로 다른 참가자
- 병원 대기 경험이 있는 성인

### 후속 검토

- 환자 또는 보호자 경험자
- 환자 경험 또는 서비스 디자인 담당자
- 병원 운영 검토자
- 모바일 접근성 검토자

초기 테스트는 실제 진료 중인 환자에게 요구하지 않는다. 실제 병원 환경 테스트는 별도 승인과 안전 검토 후 진행한다.

---

## 4. 테스트 환경

- 모바일 세로 화면
- 소리 꺼짐을 기본 조건으로 사용
- 네트워크 연결 없이 플레이 가능
- 화면 녹화는 명시적 동의가 있는 경우에만 사용
- 실제 환자정보를 입력하지 않음
- 참가자는 언제든 이유 없이 중단할 수 있음

---

## 5. 진행 절차

### 시작 전

1. 테스트 목적 설명
2. 게임이 실제 의료 도구가 아님을 고지
3. 녹화와 행동 로그 동의 확인
4. 사전 질문

사전 질문:

- 병원 대기 중 주로 무엇을 하는가?
- 병원 대기가 길게 느껴지는 가장 큰 이유는 무엇인가?
- 모바일 운영 게임 경험은 어느 정도인가?

### 플레이

진행자는 조작법을 먼저 설명하지 않는다. 참가자가 말로 생각을 표현하도록 요청하되, 막히면 즉시 정답을 알려주지 않는다.

### 종료 후

- 이해도 질문
- 체감 시간 질문
- 메시지 적절성 질문
- 다시 플레이 의향
- 불안하거나 불편했던 표현

---

## 6. 핵심 과제

1. 병원에서 가장 큰 병목을 찾는다.
2. 의료진을 한 번 재배치한다.
3. 재배치의 부작용을 설명한다.
4. 지연 환자에게 안내한다.
5. 수술 후 병상 부족 이벤트를 해결한다.
6. 게임을 잠시 나간다.
7. 다시 접속해 이어서 플레이한다.
8. 하루 결과에서 잘한 결정과 개선점을 찾는다.

---

## 7. 관찰 지표

| 지표 | 측정 방법 |
|---|---|
| 첫 결정 시간 | 시작부터 첫 유효 명령까지 |
| 병목 발견 시간 | 과제 제시부터 올바른 부서 선택까지 |
| 행동 성공률 | 도움 없이 과제 완료 |
| 차단 이해도 | 불가능한 행동의 이유를 설명 |
| 인과 이해도 | 선택이 두 지표에 미친 영향 설명 |
| 중단 성공률 | 진행 손실 없이 잠시 나가기 |
| 복귀 성공률 | 마지막 상태를 이해하고 재개 |
| 의료 오인 | 실제 의료 규칙으로 해석한 발언 |
| 메시지 오해 | 병원 지연을 정당화한다고 느낀 발언 |

## 8. 체감 대기시간 측정

초기 프로토타입에서는 임상적 효과를 주장하지 않고 주관적 인상을 측정한다.

### 질문

- 실제 플레이 시간은 몇 분이었다고 느꼈는가?
- 게임을 하지 않고 기다렸을 때보다 시간이 빠르게 갔다고 느꼈는가?
- 게임 때문에 주변 안내를 놓칠 것 같았는가?
- 중간에 멈추는 것이 부담스러웠는가?

실제 시간과 추정 시간의 차이는 참고 자료로만 사용한다. 적은 참가자 수로 체감 대기시간 감소 효과를 입증했다고 표현하지 않는다.

---

## 9. 이해도 질문

설명문을 다시 보여주지 않고 질문한다.

1. 검사 대기가 외래에 어떤 영향을 주었는가?
2. 의료진을 다른 부서로 옮길 때 어떤 비용이 생겼는가?
3. 안내는 실제 대기시간과 환자 경험에 각각 어떤 영향을 주었는가?
4. 병상 부족은 어떤 일정에 영향을 줄 수 있었는가?
5. 게임 규칙과 실제 병원 운영은 같다고 생각하는가?

70% 이상이 첫 네 질문 중 두 개 이상을 설명하고, 모든 참가자가 다섯 번째 질문에 `다르다`고 답하는 것을 초기 기준으로 한다.

---

## 10. 페이싱 관찰

참가자에게 각 구간의 느낌을 표시하게 한다.

- 지루함
- 적절함
- 복잡함
- 불안함
- 피곤함

다음 행동도 관찰한다.

- 이벤트 문구를 읽지 않고 선택
- 병원 전체 상태를 보지 않고 같은 행동 반복
- 회복 구간에서 할 일을 찾지 못함
- 정점 구간에서 정보가 너무 많음
- 결과 화면을 건너뜀

---

## 11. 디자이너 피드백 루프

각 테스트 후 다음 순서로 제품을 수정한다.

```text
사용자 의도 관찰
→ 행동 확인
→ 게임 피드백 해석 확인
→ 정신 모델의 오해 기록
→ 가장 작은 설계 수정
→ 같은 과제로 재검증
```

사용자가 못한 행동을 즉시 튜토리얼 문장으로 해결하지 않는다. 먼저 랜드마크, 정보 계층, 차단 피드백과 인과 표시가 부족한지 확인한다.

---

## 12. 문제 심각도

| 등급 | 기준 |
|---|---|
| S0 | 의료 오인, 개인정보, 실제 안전 위험 |
| S1 | 진행 불가, 저장 손실, 진료 호출 방해 가능성 |
| S2 | 핵심 루프 또는 인과관계 이해 실패 |
| S3 | 반복 조작 불편, 정보 탐색 지연 |
| S4 | 미세한 문구, 장식과 연출 문제 |

S0와 S1 문제는 해결 전 외부 테스트를 중단한다.

---

## 13. 초기 성공 기준

- 80% 이상이 3분 안에 첫 유효 결정을 완료
- 80% 이상이 가장 큰 병목을 5초 안에 발견
- 70% 이상이 한 선택의 장단점 두 가지를 설명
- 전원이 잠시 나가기와 이어하기를 성공
- 70% 이상이 시간이 빠르게 갔다고 응답
- 전원이 게임과 실제 의료 규칙이 다르다고 이해
- 병원 지연을 정당화한다고 응답한 참가자가 없음
- 실제 의료 판단으로 오해한 참가자가 없음

참가자 5명의 결과는 방향성 검증으로만 사용한다.
