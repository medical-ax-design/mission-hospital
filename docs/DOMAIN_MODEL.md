# 현재 도메인 모델

이 문서는 실행 중인 보호자 동행 프로토타입의 상태와 불변 규칙을
정의한다. 데이터베이스 설계가 아니라 현재 메모리 도메인과 공유
Zod 계약을 설명한다.

## 1. CaregiverJourney

`CaregiverJourney`는 현재 선택된 가상 환자 여정이다.

| 필드 | 의미 |
|---|---|
| `scenarioId` | `gastric-surgery` 또는 `morning-colonoscopy` |
| `linked` | 보호자 연결 완료 여부 |
| `patient` | 가상 환자와 검사·수술 일정 |
| `treatment` | 병원이 확인한 현재 상태 |
| `task` | 현재 보호자 행정업무 또는 `null` |
| `guide` | 목적 기반 이동 안내 또는 `null` |
| `schedules` | 날짜·장소·준비사항이 등록된 환자 일정 배열 |

시나리오를 선택하면 가상 여정 전체를 초기 상태로 다시 만든다.
클라이언트가 환자나 상태를 조합하지 않는다.

## 2. PatientSchedule

| 필드 | 의미 |
|---|---|
| `type` | 진료·검사·입원·수술·행정 일정 구분 |
| `startsAt` | 병원 일정 시작 시각 |
| `building` | `MAIN`, `ANNEX`, `CANCER` |
| `floor` | 층별 안내도와 일치하는 층 |
| `location` | 병원이 등록한 목적지 명칭 |
| `preparation` | 보호자가 확인할 준비사항 |

일정은 한 개 이상이어야 하며 Web은 `Asia/Seoul` 날짜로 묶어 월간
달력에 표시한다. 사용자가 선택한 빈 날짜에는 일정을 추측하지 않는다.

## 3. RestrictionGuidance

대장내시경 시나리오의 제한 안내는 보호자 여정과 분리된 도메인이다.

```text
현재 scenarioId
→ 현재 RestrictionPhase
→ 같은 phase의 공식 RestrictionRule
→ 목록 또는 검색 결과
```

단계 순서:

1. `THREE_DAYS_BEFORE`
2. `DAY_BEFORE`
3. `ABSOLUTE_FASTING`

마지막 단계에서 추가 전환 요청이 와도 상태를 유지한다.
`DAY_BEFORE`는 검사 전날 식사와 자정 이후 금식 안내를 나타내고,
`ABSOLUTE_FASTING`은 검사 당일 오전 5시부터 검사 종료 전까지다.
따라서 검사 준비 과정에서 필요한 장 정결제 복용 시간과 절대 금식을
같은 시각으로 취급하지 않는다.

## 4. 제한 결과 불변 조건

결과는 다음 두 값만 가진다.

- `DO_NOT_PROVIDE`: 현재 단계의 공식 규칙과 명시적으로 일치
- `CHECK_BEFORE_PROVIDING`: 일치 규칙이 없거나 환자별 확인 필요

허가 상태는 계약에 존재하지 않는다. 검색어가 공식 규칙과 일치하지
않아도 허용을 추론하지 않는다. 약물 규칙은 복용 지시가 아니라 확인
필요 결과만 반환한다.

모든 결과는 공식 출처 제목, URL, 확인일과 데이터 버전을 가진다.

## 5. 검색 규칙

- 앞뒤 공백을 제거하고 한국어 소문자 기준으로 정규화한다.
- 입력은 1자 이상 80자 이하의 단일 문자열이어야 한다.
- 현재 단계의 대표 항목과 사전 등록 별칭만 완전 일치시킨다.
- 다른 단계의 규칙은 검색 결과에 사용하지 않는다.
- 일치하지 않으면 `CHECK_BEFORE_PROVIDING`을 반환한다.

## 6. SavedQuestion

| 상태 | 의미 |
|---|---|
| `OPEN` | 의료진에게 확인할 질문 |
| `DONE` | 보호자가 상담 여부를 확인함 |

같은 여정에서 같은 정규화 검색어의 `OPEN` 질문은 중복 생성하지
않는다. 완료는 답변을 저장하지 않으며 `completedAt`만 기록한다.
질문과 제한 상태는 현재 프로토타입에서 API 메모리에만 저장된다.

## 7. 실내 길찾기 화면 모델

실내 길찾기는 서버의 환자 목적지와 클라이언트의 수동 현재 위치를
결합한다.

- `HospitalMap`: 건물, 층, 삼성서울병원 공식 이미지 URL과 원문 URL
- `IndoorLocation`: 건물, 층, 가까운 랜드마크
- `RouteMode`: `ELEVATOR` 또는 `ESCALATOR`
- `IndoorRouteStep`: 지도 위 붉은 경로 또는 건물·층 전환 안내

공개 안내도는 경로 그래프가 아니므로 프로토타입 경로는 검증된 데모
랜드마크에만 제공한다. 자동 현 위치, 경로 이탈 감지와 실시간 폐쇄
반영은 이 모델의 범위가 아니다.
