# Wait:ON 게임 디자인 자료 반영 기록

## 문서 목적

사용자가 제공한 게임 디자인 영상 스크립트에서 추출한 원칙과 Wait:ON 적용 결정을 추적한다. 영상의 사례를 그대로 복제하지 않고 프로젝트 목표, 의료 안전과 MVP 범위에 맞게 변환한다.

---

## 1. 반영 기준

각 인사이트는 다음 질문을 통과해야 한다.

1. 체감 대기시간 감소에 기여하는가?
2. 병원 운영의 연결 구조를 이해하게 하는가?
3. 환자 경험을 우선하는가?
4. 중단과 복귀를 방해하지 않는가?
5. 실제 의료 판단으로 오해되지 않는가?
6. 5일 MVP 범위에 맞는가?

## 7. 타이쿤 장르 비교

일반 타이쿤에서 채택하는 요소:

- 연결된 처리 체인
- 부서별 자원
- 동적 사건
- 고객 또는 이용자 만족
- 건물 단면과 공간 랜드마크

채택하지 않는 요소:

- 수익 극대화
- 병실 가격과 매출
- 경쟁 병원 제압
- 무한 시설 확장
- 선형 능력치 업그레이드
- 환자를 수익원이나 방해물로 표현

Wait:ON의 장르 정의:

> 병원을 확장하는 타이쿤이 아니라 연결된 부서의 시간과 처리 용량을 조정하는 환자 경험 시뮬레이션

## 8. 제작 방식

| 자료 주제 | 채택한 원칙 | 적용 |
|---|---|---|
| 게임 엔진 선택 | 배포 환경과 핵심 메커니즘에 맞는 도구 선택 | React·TypeScript 웹 MVP |
| 튜토리얼 의존 | 코드를 복사하지 않고 규칙과 문서를 이해 | 순수 게임 엔진과 공식 문서 중심 |
| 아트 우선 위험 | 플레이 가능한 루프 전에 에셋을 과제작하지 않음 | 임시 도형과 SVG 우선 |
| 진행 기록 | 보이지 않는 설계·검증 작업도 기록 | 문서와 커밋으로 결정 추적 |
| 커뮤니티 피드백 | 사용자와 검토자의 관찰로 설계 개선 | 환자 경험·의료 운영·접근성 검토 |

## 9. MVP와 후속 적용 구분

### MVP

- 고정 이벤트와 고정 난수 시드
- 외래·검사 닫힌 루프부터 구현
- 데이터 기반 작업과 효과
- 병목과 차단 이유 표시
- 9분 페이싱
- 자동 저장과 이어하기
- 고정 그림자, 그라데이션과 약한 효과

### 후속

- 제약 기반 셔플백
- 전개·정점·회복 운영 디렉터
- 병동과 중환자실
- 일정 프리셋과 운영 자동화
- 선택형 고급 시나리오
- 제한된 2D 노멀 맵과 환경 변화

### 제외

- 멀티플레이 넷코드
- 3D 스카이박스
- 모든 에셋의 노멀 맵
- 순수 확률 기반 고압 이벤트
- 영구 능력치 상승
- 중독적 재방문 장치
- 환자 안전을 베팅하는 선택
