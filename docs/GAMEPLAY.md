# Wait:ON 게임플레이 명세

## 문서 정보

- 상위 문서: [`PROJECT_V2.md`](./PROJECT_V2.md)
- 문서 목적: MVP의 게임 루프, 상태, 운영 규칙, 이벤트, 평가 및 저장 방식을 정의한다.
- 적용 범위: 모바일 세로형 웹 프로토타입
- 설계 원칙: 실제 의료 판단이 아닌 가상의 병원 운영 퍼즐로 구현한다.

## 1. 게임플레이 목표

사용자는 대형병원의 운영 책임자가 되어 하나의 병원을 하루 동안 운영한다.

게임의 목표는 모든 환자를 가장 빨리 처리하는 것이 아니다. 다음 요소를 균형 있게 관리해 환자 경험을 개선하는 것이다.

- 환자 만족도
- 평균 대기시간
- 의료진 피로도
- 환자 안전
- 안내 정확도
- 병원 운영 효율

각 결정은 하나의 지표만 개선하지 않는다. 예를 들어 의료진을 응급실에 추가 배치하면 안전과 응급실 대기는 개선될 수 있지만, 외래 대기와 의료진 피로는 증가할 수 있다.

---

## 2. MVP 플레이 경험

### 플레이 단위

- 하나의 플레이 단위는 병원의 하루다.
- 병원 시간은 08:30부터 17:30까지 흐른다.
- 기본 속도에서 현실 시간 1초는 게임 시간 1분에 해당한다.
- 이벤트 선택, 튜토리얼, 결과 화면에서는 시간이 자동으로 멈춘다.
- 한 병원 하루는 이벤트 선택 시간을 제외하면 약 9분이다.
- 사용자는 언제든 일시정지하거나 “잠시 나가기”를 선택할 수 있다.

### 진행 구조

게임은 스테이지 선택 화면을 제공하지 않는다. 하루 운영이 끝나면 결과를 확인하고 다음 날 운영으로 이어지는 구조를 사용한다.

MVP에서는 한 번의 하루 시나리오를 완성도 있게 구현한다. 다음 날 시작 기능은 같은 시나리오를 초기화해 재도전하는 방식으로 제공하며, 장기 성장 시스템은 포함하지 않는다.

### 핵심 게임 루프

```text
병원 상태 확인
  ↓
환자 도착 및 대기열 변화
  ↓
의료진 배치 또는 일정 조정
  ↓
진료·검사·수술 처리
  ↓
예정 또는 돌발 이벤트 발생
  ↓
운영 선택
  ↓
지표와 병원 상태 변화 확인
  ↓
다음 환자와 사건으로 진행
```

## 3. 사용자 조작

### 기본 조작

- 부서 선택: 병원 단면에서 부서를 탭한다.
- 환자 확인: 부서 대기열에서 환자 카드를 탭한다.
- 의료진 배치: 의료진 카드를 배치 가능한 부서로 드래그하거나 탭으로 지정한다.
- 일정 조정: 충돌이 발생한 일정에서 2~3개 선택지 중 하나를 선택한다.
- 환자 안내: 지연 환자를 선택하고 안내 행동을 실행한다.
- 이벤트 대응: 이벤트 카드의 선택지 중 하나를 선택한다.
- 시간 제어: 일시정지, 1배속, 2배속을 선택한다.
- 중단: “잠시 나가기”를 눌러 저장 후 홈으로 이동한다.

### 조작 원칙

- 핵심 행동은 한 손으로 수행할 수 있어야 한다.
- 드래그가 어려운 사용자를 위해 모든 드래그 조작은 탭 방식으로도 수행할 수 있어야 한다.
- 잘못된 배치는 적용 전에 결과를 보여주거나 즉시 되돌릴 수 있어야 한다.
- 이벤트 선택에는 짧고 명확한 예상 영향 설명을 제공한다.

## 4. 병원 단면과 부서

MVP 병원은 네 개의 운영 부서, 간이 병상 자원과 공용 정보 영역으로 구성한다.

### 외래

- 예약 및 당일 방문 환자가 진료를 기다린다.
- 의사가 배치되어야 환자를 처리할 수 있다.
- 검사 처방을 받은 환자는 검사실로 이동한다.
- 의사가 응급실이나 수술실로 이동하면 외래 대기가 증가한다.

### 검사실

- MVP에서는 혈액검사와 영상검사를 하나의 검사실로 단순화한다.
- 검사 인력과 장비가 모두 이용 가능해야 환자를 처리할 수 있다.
- 검사 완료 환자는 외래로 돌아가 결과 확인을 기다린다.
- 장비 점검 이벤트가 발생하면 처리 용량이 일시적으로 감소한다.

### 응급실

- 가상의 응급 이벤트로 도착한 환자를 처리한다.
- 응급실 환자는 실제 의료 분류 체계를 사용하지 않는다.
- 이벤트 카드가 요구하는 의료진과 공간을 제한 시간 안에 확보하는 운영 퍼즐로 표현한다.
- 응급실 자원 배치는 다른 부서의 대기와 일정에 영향을 준다.

### 수술실

- 미리 예정된 수술 일정이 존재한다.
- 담당 의사, 간호사와 수술실이 모두 준비되어야 시작된다.
- 응급실 또는 검사실 지연이 수술 시작 시각에 영향을 줄 수 있다.
- 실패는 자극적인 의료 결과가 아니라 “일정 지연” 또는 “운영 위험 증가”로 표현한다.

### 간이 병상 자원

- 병동을 독립된 운영 공간으로 제공하지 않고, 1인실·2인실·6인실의 전체 병상과 남은 병상만 표시한다.
- 수술 후 입원 대기 이벤트가 발생하면 사용자는 가상 환자의 병실 선호와 현재 공석을 확인한다.
- 사용자는 희망 병실이 날 때까지 기다리며 예상시간을 안내하거나, 환자가 수용할 수 있는 다른 병실을 제안할 수 있다.
- 병실 배정은 환자 만족도와 대기시간에 영향을 주지만 수익이나 매출에는 영향을 주지 않는다.
- 실제 감염 관리, 성별, 질환 또는 경제 상황에 따른 배정 규칙은 다루지 않는다.
- 입·퇴원, 청소, 병실 이동과 병동 인력 배치는 후속 버전의 병동 운영 시스템으로 확장한다.

### 공용 정보 영역

- 병원 시간
- 진행 중인 주요 일정
- 핵심 지표
- 의료진 현황
- 병실 유형별 남은 병상
- 현재 이벤트
- 일시정지 및 잠시 나가기

## 5. 초기 병원 구성

MVP 하루는 다음 자원으로 시작한다.

### 의료진

| 역할 | 수 | 기본 배치 |
|---|---:|---|
| 외래 의사 | 2 | 외래 |
| 응급 담당 의사 | 1 | 응급실 |
| 수술 담당 의사 | 1 | 수술 준비 |
| 간호사 | 4 | 외래 1, 검사실 1, 응급실 1, 수술실 1 |
| 검사 담당자 | 1 | 검사실 |

### 시설

| 시설 | 동시 처리 용량 |
|---|---:|
| 외래 진료실 | 2 |
| 검사실 | 1 |
| 응급 처치 공간 | 1 |
| 수술실 | 1 |

### 간이 병상

| 병실 유형 | 전체 병상 | 하루 시작 시 남은 병상 |
|---|---:|---:|
| 1인실 | 1 | 0 |
| 2인실 | 2 | 1 |
| 6인실 | 6 | 1 |

MVP에서는 병상 부족 이벤트에 필요한 공석만 상태로 관리한다. 기존 입원 환자의 개별 상태는 시뮬레이션하지 않는다.

### 초기 지표

| 지표 | 초기값 |
|---|---:|
| 환자 만족도 | 75 |
| 환자 안전 | 90 |
| 안내 정확도 | 70 |
| 의료진 피로도 | 15 |
| 운영 효율 | 70 |

평균 대기시간은 처리된 환자의 실제 게임 내 대기시간으로 계산하므로 별도 초기 점수를 갖지 않는다.

## 6. 환자 모델과 환자 AI

### 환자 데이터

모든 환자는 다음 정보를 가진다.

| 속성 | 설명 |
|---|---|
| `id` | 가상 환자 식별자 |
| `displayName` | 개인을 식별하지 않는 가상 이름 |
| `arrivalTime` | 병원 도착 시각 |
| `appointmentTime` | 예약이 있는 경우 예정 시각 |
| `path` | 거쳐야 하는 부서 순서 |
| `currentState` | 현재 진행 상태 |
| `currentDepartment` | 현재 위치 |
| `waitStartedAt` | 현재 대기 시작 시각 |
| `expectedDuration` | 현재 처리에 필요한 시간 |
| `waitTolerance` | 만족도 감소가 시작되는 대기시간 |
| `informationNeed` | 안내가 필요한 정도 |
| `fictionalPriority` | 게임 이벤트용 우선 처리 등급 |
| `roomPreference` | 병상 이벤트에서 사용하는 가상의 병실 선호 |

`fictionalPriority`는 게임 전용 값이며 실제 증상이나 응급도 분류와 연결하지 않는다.

### 환자 상태

```text
예정
 → 도착
 → 접수
 → 부서 대기
 → 처리 중
 → 다음 부서 이동
 → 완료
```

검사가 필요한 외래 환자는 다음 흐름을 따른다.

```text
외래 대기
 → 외래 진료
 → 검사 대기
 → 검사
 → 외래 결과 대기
 → 결과 확인
 → 완료
```

### 환자 AI 규칙

환자 AI는 규칙 기반 상태 머신이다.

1. 도착 시각이 되면 지정된 부서 대기열에 들어간다.
2. 필요한 인력과 시설이 비어 있으면 처리를 시작한다.
3. 처리가 완료되면 경로의 다음 부서로 이동한다.
4. 대기 허용 시간을 넘으면 만족도가 단계적으로 감소한다.
5. 안내 필요도가 높은 환자는 안내가 없을 때 만족도가 더 빠르게 감소한다.
6. 정확한 안내를 받으면 일정 시간 동안 만족도 감소가 완화된다.
7. 이벤트 환자는 이벤트가 지정한 별도 운영 규칙을 따른다.

환자는 사망하거나 자극적인 상태로 악화되지 않는다. 처리 지연은 만족도 감소, 일정 변경, 안전 지표 하락으로 표현한다.

## 7. 의료진 모델과 일정

### 의료진 데이터

| 속성 | 설명 |
|---|---|
| `id` | 의료진 식별자 |
| `role` | 의사, 간호사, 검사 담당자 |
| `skills` | 배치 가능한 부서 |
| `currentDepartment` | 현재 위치 |
| `schedule` | 예정 업무 목록 |
| `currentTask` | 수행 중인 업무 |
| `fatigue` | 0~100 피로도 |
| `availableAt` | 다음 업무 가능 시각 |

### 일정 규칙

- 의료진은 기본 일정에 따라 부서에 배치된다.
- 사용자는 허용된 의료진만 다른 부서로 재배치할 수 있다.
- 재배치에는 게임 시간 5분의 이동 및 준비 시간이 필요하다.
- 처리 중인 업무를 완료하지 않고 이동할 수 없다.
- 예정 업무 시작 15분 전부터 일정 충돌 알림을 제공한다.
- 일정이 충돌하면 대체 인력 배치, 일정 지연, 현재 업무 우선 중 하나를 선택한다.

### 피로도 규칙

- 업무 수행 중 피로도가 증가한다.
- 기본 업무는 게임 시간 10분마다 피로도 1이 증가한다.
- 응급 이벤트 대응과 연속 재배치는 추가 피로도를 발생시킨다.
- 휴식 상태에서는 게임 시간 10분마다 피로도 2가 감소한다.
- 피로도 70 이상이면 처리 속도가 10% 감소한다.
- 피로도 90 이상이면 추가 업무 배치가 제한된다.

피로도는 의료진 개인의 책임이 아니라 운영자가 관리해야 하는 시스템 제약으로 표현한다.

## 8. 처리 및 대기 규칙

### 처리 시작 조건

환자 처리는 다음 조건이 모두 충족될 때 시작한다.

1. 환자가 해당 부서 대기열의 처리 대상이다.
2. 필요한 시설에 여유가 있다.
3. 필요한 역할의 의료진이 배치되어 있다.
4. 해당 의료진이 다른 업무를 수행 중이지 않다.
5. 이벤트로 부서가 중지된 상태가 아니다.

### 대기열 결정

일반 대기열은 다음 순서로 처리한다.

1. 게임 이벤트가 지정한 우선 처리 대상
2. 예약 시각을 넘긴 환자
3. 대기 허용 시간에 가까운 환자
4. 먼저 도착한 환자

사용자는 대기열을 직접 조정할 수 있지만, 조정 이유와 예상 영향을 확인해야 한다. 게임은 이 규칙이 실제 의료 현장의 진료 우선순위를 나타내지 않는다고 명시한다.

### 안내 행동

지연된 환자에게 다음 안내를 제공할 수 있다.

- 현재 진행 단계 알림
- 변경된 예상 대기구간 알림
- 지연 원인에 대한 비의료적 설명

안내에는 정확한 시각 대신 “곧”, “조금 지연”, “대기 증가”처럼 모호한 표현을 남발하지 않는다. 게임이 계산한 범위형 예상시간을 제공한다.

안내 후 상황이 바뀌면 이전 안내를 갱신해야 한다. 갱신하지 않은 정보는 안내 정확도를 낮춘다.

## 9. 이벤트 시스템

### 이벤트 종류

1. **예정 이벤트:** 수술 시작, 예약 환자 집중 도착, 점검 일정
2. **돌발 이벤트:** 응급환자 도착, 의료진 일시 이탈, 장비 문제
3. **환자 경험 이벤트:** 지연 문의, 보호자 안내 요청, 일정 변경 고지

### 이벤트 구성

| 속성 | 설명 |
|---|---|
| `id` | 이벤트 식별자 |
| `title` | 이벤트 제목 |
| `description` | 비자극적 상황 설명 |
| `trigger` | 발생 시각 또는 상태 조건 |
| `choices` | 2~3개의 운영 선택 |
| `effects` | 자원, 일정, 지표 변화 |
| `duration` | 이벤트 지속 시간 |
| `cooldown` | 유사 이벤트 재발 제한 |
| `safetyNote` | 필요한 경우 실제 의료와 다름을 알리는 문구 |

### 발생 규칙

- MVP 하루에는 예정 이벤트 2개, 돌발 이벤트 2개, 환자 경험 이벤트 2개가 발생한다.
- 동시에 중요한 선택 이벤트는 하나만 표시한다.
- 새 이벤트가 발생하면 게임 시간이 자동으로 멈춘다.
- 선택에 제한시간을 두지 않는다.
- 같은 유형의 돌발 이벤트는 60초 안에 반복 발생하지 않는다.
- 한 이벤트의 결과가 다른 부서 일정에 영향을 줄 수 있다.

### MVP 이벤트 세트

| 유형 | 이벤트 | 핵심 선택 |
|---|---|---|
| 예정 | 오전 외래 집중 | 외래 인력 유지 / 검사 병목 선제 대응 |
| 예정 | 오후 의료진 피로 | 휴식 교대 / 현재 운영 유지 |
| 돌발 | 검사 장비 점검 | 일부 검사 지연 / 일정 재배치 및 안내 |
| 돌발 | 응급환자 도착 | 응급실 추가 지원 / 현재 배치 유지 |
| 환자 경험 | 수술 후 병상 부족 | 희망 병실 대기 및 안내 / 가능한 병실 제안 |
| 환자 경험 | 외래 지연 안내 요청 | 예상시간 갱신 / 인력 재배치 후 안내 |

선택지에는 정답 하나를 숨겨두기보다 서로 다른 장단점을 제공한다.

### 병상 부족 이벤트 규칙

- 병실 선호는 “1인실 선호” 또는 “다인실 이용 가능” 두 가지로만 단순화한다.
- 1인실을 선호하는 환자에게 공석이 없으면 대기 및 안내 선택을 제공한다.
- 환자가 다인실 이용이 가능한 경우 2인실 또는 6인실의 남은 병상을 제안할 수 있다.
- 희망 병실 대기는 대기시간을 증가시키지만 정확한 안내로 만족도 감소를 완화할 수 있다.
- 다른 병실 제안을 환자가 수용하면 해당 병실의 남은 병상은 1 감소하고 입원 대기는 종료된다.
- 선호와 다른 병실을 수용하면 해당 환자의 만족도가 2 감소한다. 이 감소는 빠른 병상 배정으로 줄어드는 대기시간과 함께 평가한다.
- 실제 병실 비용, 보험, 질환, 감염 관리 또는 의학적 배정 조건은 사용하지 않는다.

## 10. 지표 계산

모든 점수형 지표는 0~100 범위로 제한한다.

### 환자 만족도

다음 요소를 환자별로 계산한 뒤 평균한다.

- 모든 환자는 만족도 75로 시작한다.
- 대기 허용 시간 안에 처리 시작하면 5 증가한다.
- 대기 허용 시간을 넘기면 게임 시간 5분마다 3 감소한다.
- 정확한 진행 안내를 받으면 4 증가한다.
- 잘못되거나 오래된 안내를 받으면 4 감소한다.
- 일정 변경을 사전에 안내하면 3 증가한다.
- 설명 없이 일정이 변경되면 6 감소한다.

환자별 만족도는 0~100 범위로 제한한다. 같은 안내를 반복해서 점수를 얻을 수 없도록 한 상태 변화당 한 번만 반영한다.

### 평균 대기시간

완료한 환자들이 각 부서에서 기다린 게임 내 시간의 평균이다. 처리 시간과 부서 간 이동 시간은 대기시간에 포함하지 않는다.

### 의료진 피로도

모든 근무 의료진의 현재 피로도 평균이다. 낮을수록 좋은 값이지만 화면에서는 “의료진 피로도” 원값으로 표시한다.

### 환자 안전

- 기본값은 90이다.
- 필수 자원 없이 처리를 시도할 수 없으므로 단순 오조작으로 안전이 감소하지 않는다.
- 이벤트 요구를 장시간 해결하지 않거나 피로가 높은 의료진에게 업무를 집중할 때 감소한다.
- 적절한 지원과 휴식 교대로 회복할 수 있다.

안전 지표 하락은 실제 환자의 악화나 사망으로 표현하지 않는다.

### 안내 정확도

- 현재 일정과 일치하는 안내 제공: 3 증가
- 일정 변경 후 안내 갱신: 4 증가
- 오래된 예상시간 방치: 5 감소
- 실제 진행 상태와 다른 안내: 8 감소

안내 정확도는 70에서 시작하며 0~100 범위로 제한한다.

### 운영 효율

운영 시간 중 사용 가능한 시설과 의료진이 적절히 활용된 비율이다. 무조건 높은 가동률을 요구하지 않으며, 필요한 휴식은 비효율로 처리하지 않는다.

### 하루 종합 PX 점수

```text
PX 점수 =
  환자 만족도 × 0.25
  + 대기시간 점수 × 0.20
  + 환자 안전 × 0.25
  + 안내 정확도 × 0.15
  + 피로 관리 점수 × 0.10
  + 운영 효율 × 0.05
```

- 대기시간 점수는 평균 대기시간이 게임 시간 10분 이하면 100점이다. 10분을 넘긴 뒤부터 1분마다 2점씩 감소하며 최저점은 0점이다.
- 피로 관리 점수는 `100 - 의료진 피로도`로 계산한다.
- PX 점수는 돈이나 병원 규모로 환산하지 않는다.

## 11. 성공, 종료와 피드백

### 하루 종료

17:30이 되면 남은 작업을 요약하고 하루 운영을 종료한다.

### 중도 종료

- 사용자가 “잠시 나가기”를 선택하면 실패로 처리하지 않는다.
- 브라우저가 백그라운드로 전환되어도 병원 시간은 진행되지 않는다.
- 저장된 상태로 이어서 플레이할 수 있다.

### 운영 위험 상태

환자 안전이 20 아래로 내려가면 게임 시간을 멈추고 운영 위험 알림을 제공한다. 사용자는 인력 재배치, 일정 중단, 휴식 배정 중 하나를 선택해 운영을 재개한다.

게임은 자극적인 실패 화면을 사용하지 않는다. 하루 결과는 “성공/실패”보다 다음 세 단계로 피드백한다.

- 안정적인 운영
- 개선이 필요한 운영
- 운영 위험이 높았던 하루

### 결과 화면

- 종합 PX 점수
- 환자 만족도
- 평균 대기시간
- 의료진 피로도
- 환자 안전
- 안내 정확도
- 운영 효율
- 잘한 결정 2개
- 다음 플레이에서 개선할 결정 1개
- 다시 운영하기
- 홈으로

피드백은 사용자의 선택을 비난하지 않고 선택과 결과의 인과관계를 설명한다.

## 12. 튜토리얼

첫 플레이는 3분 안에 핵심 조작을 이해하도록 단계적으로 안내한다.

1. 병원 단면에서 외래를 선택한다.
2. 대기 환자와 현재 자원을 확인한다.
3. 의료진 한 명을 배치한다.
4. 환자 안내 행동을 실행한다.
5. 이벤트 선택지의 예상 영향을 확인하고 결정한다.
6. 일시정지와 “잠시 나가기” 위치를 확인한다.

튜토리얼 중에도 자동 저장을 수행한다. 다시 접속하면 완료하지 않은 튜토리얼 단계부터 이어간다.

## 13. 화면 흐름

```text
시작 화면
 ├─ 새로 시작
 ├─ 이어하기
 ├─ 프로젝트 및 의료 안전 안내
 └─ 설정
      ↓
첫 플레이 안내
      ↓
병원 단면
 ├─ 부서 상세
 ├─ 의료진 배치
 ├─ 환자 및 대기열
 ├─ 이벤트 선택
 ├─ 일정
 ├─ 일시정지
 └─ 잠시 나가기
      ↓
하루 결과
 ├─ 다시 운영하기
 └─ 홈으로
```

### 시작 화면

- 저장 데이터가 있으면 “이어하기”를 가장 강조한다.
- “새로 시작”을 선택해 기존 저장을 덮어쓸 때 확인 절차를 제공한다.

### 병원 단면

- 상단: 병원 시간, 일시정지, 핵심 경고
- 중앙: 네 개 부서가 보이는 병원 단면
- 하단: 현재 선택한 환자 또는 의료진 카드
- 이벤트 발생 시: 화면 위 카드 형태의 선택 패널
- 항상 접근 가능한 위치: “잠시 나가기”

### 부서 상세

- 현재 처리 중인 환자
- 대기열
- 배치 의료진
- 시설 상태
- 예정 일정
- 가능한 운영 행동

## 14. 자동 저장 및 이어하기

### 저장 항목

- 저장 데이터 버전
- 현재 병원 날짜와 시각
- 게임 속도와 일시정지 상태
- 환자 목록과 상태
- 의료진 목록, 일정, 피로도와 현재 업무
- 시설 상태
- 병실 유형별 전체 병상과 남은 병상
- 대기열
- 발생 및 종료된 이벤트
- 활성 이벤트와 선택 상태
- 현재 지표
- 튜토리얼 진행 상태
- 마지막 저장 시각

### 저장 시점

- 배치, 일정 조정, 안내 또는 이벤트 선택 확정 직후
- 환자 또는 의료진의 주요 상태 전이 직후
- 이벤트 시작 및 종료 직후
- 15초마다
- `visibilitychange`로 백그라운드 진입이 감지될 때
- `pagehide`가 감지될 때
- “잠시 나가기”를 선택할 때

앱 종료 이벤트는 브라우저 환경에서 항상 보장되지 않는다. 따라서 마지막 행동 직후 저장을 우선하며, 정상 플레이에서 잃을 수 있는 진행은 최대 15초로 제한한다.

### 복귀 규칙

- 이탈 중에는 게임 시간이 흐르지 않는다.
- 활성 이벤트가 있으면 선택 전 상태로 복귀한다.
- 처리 중이던 업무는 저장된 남은 시간부터 계속된다.
- 저장 데이터가 손상되면 마지막 정상 저장본을 사용한다.
- 정상 저장본도 복구할 수 없으면 새 게임을 안내하되 기존 데이터를 즉시 삭제하지 않는다.

### MVP 저장 기술 원칙

- 저장 기능은 게임 상태와 분리된 저장 어댑터를 통해 사용한다.
- 첫 웹 MVP는 브라우저 로컬 저장소를 사용한다.
- 저장 데이터에는 `schemaVersion`을 포함한다.
- 실제 환자정보, 사용자 이름, 연락처와 의료정보는 저장하지 않는다.

## 15. 오디오, 알림과 접근성

- 모든 핵심 정보는 무음 상태에서도 이해할 수 있다.
- 소리는 기본적으로 낮은 강도이며 사용자가 즉시 끌 수 있다.
- 진동을 필수 피드백으로 사용하지 않는다.
- 이벤트는 색상, 아이콘과 텍스트를 함께 사용해 구분한다.
- 작은 글자를 강제하지 않고 운영 정보의 우선순위를 나눈다.
- 중요하지 않은 반복 애니메이션은 줄인다.
- 진료 호출 등 주변 상황을 확인하라는 안내를 시작 화면과 일시정지 화면에 제공한다.

## 16. 의료 안전 표현 규칙

### 허용

- “가상의 운영 상황입니다.”
- “실제 진료 우선순위와 다르게 단순화되어 있습니다.”
- “현재 몸 상태에 문제가 있으면 게임을 멈추고 현장 의료진에게 알려주세요.”
- 지연, 일정 변경, 자원 충돌, 안내 부족과 같은 운영 표현

### 금지

- 실제 증상에 따른 진료 우선순위 제안
- “이 증상은 안전하다”와 같은 의학적 판단
- 실제 대기시간이나 수술 진행 상황처럼 보이는 정보
- 사망, 수술 실패, 심각한 악화를 점수 연출로 사용
- 환자 불만을 방해 요소나 적으로 표현
- 의료진을 무능하거나 게으른 인물로 표현
- 병원 사정을 이해해야 한다는 훈계성 문구

## 17. MVP 콘텐츠 규모

첫 구현에서는 다음 규모를 유지한다.

- 병원 하루 시나리오 1개
- 운영 부서 4개
- 간이 병상 자원 1개
- 의료진 9명
- 가상 환자 12명
- 예정 이벤트 2개
- 돌발 이벤트 2개
- 환자 경험 안내 이벤트 2개
- 하루 결과 피드백 유형 6개

콘텐츠 수를 늘리기보다 하나의 하루에서 부서 간 연쇄 영향과 자동 저장 복귀를 안정적으로 보여주는 데 집중한다.

## 18. MVP 수용 기준

다음 조건을 모두 충족하면 게임플레이 MVP가 완성된 것으로 판단한다.

1. 새 게임으로 08:30부터 하루 운영을 시작할 수 있다.
2. 외래, 검사실, 응급실과 수술실의 상태를 병원 단면에서 확인할 수 있다.
3. 1인실, 2인실과 6인실의 남은 병상을 공용 자원으로 확인할 수 있다.
4. 병상 부족 이벤트에서 대기 안내 또는 가능한 병실 제안을 선택할 수 있다.
5. 환자가 규칙에 따라 도착하고 부서 사이를 이동한다.
6. 의료진 일정과 재배치가 처리 속도 및 피로도에 반영된다.
7. 예정 이벤트와 돌발 이벤트가 발생하고 선택 결과가 상태에 적용된다.
8. 여섯 개 평가 지표가 플레이에 따라 변화한다.
9. 게임을 중단하고 재접속해 마지막 확정 상태에서 이어갈 수 있다.
10. 모바일 세로 화면에서 핵심 조작을 수행할 수 있다.
11. 색상이나 소리만으로 전달되는 핵심 정보가 없다.
12. 실제 의료정보 입력이나 의료 판단 기능이 없다.
13. 하루 종료 후 선택과 결과의 관계를 확인할 수 있다.
14. 모든 핵심 게임 규칙을 UI와 분리해 자동 테스트할 수 있다.
