# Wait:ON UX 흐름 및 화면 명세

## 문서 정보

- 상위 문서: [`PROJECT_V2.md`](./PROJECT_V2.md), [`GAMEPLAY.md`](./GAMEPLAY.md)
- 관련 시스템: [`SYSTEMS.md`](./SYSTEMS.md)
- 문서 목적: 모바일 병원 단면의 정보 계층, 탐색 경로, 행동 피드백, 중단과 복귀를 정의한다.

---

## 1. UX 목표

1. 사용자는 3분 안에 첫 운영 결정을 내린다.
2. 현재 가장 중요한 병목을 5초 안에 찾는다.
3. 핵심 행동은 병원 전체 화면에서 최대 세 단계 안에 도달한다.
4. 행동 전 예상 영향과 행동 후 실제 결과를 모두 확인한다.
5. 모든 화면에서 한 번의 조작으로 일시정지하거나 나갈 수 있다.
6. 색상과 소리 없이도 상태를 이해한다.

---

## 2. 전체 사용자 흐름

```text
시작
├─ 이어하기
├─ 새로 시작
├─ 이 게임은 가상 운영 상황이라는 안내
└─ 설정
    ↓
첫 플레이 학습
    ↓
병원 전체 단면
├─ 부서 확대
│   ├─ 대기열
│   ├─ 의료진
│   ├─ 시설
│   └─ 운영 행동
├─ 전체 일정
├─ 병상 현황
├─ 이벤트 선택
├─ 일시정지
└─ 잠시 나가기
    ↓
하루 결과
├─ 선택과 결과 분석
├─ 다시 운영하기
└─ 홈
```

저장 데이터가 있으면 `이어하기`를 기본 행동으로 제공한다. 새 게임은 기존 저장을 덮어쓸 수 있음을 확인한 뒤 시작한다.

## 3. 메인 경로와 랜드마크

### 메인 운영 경로

```text
병원 전체
→ 문제가 발생한 부서
→ 부서 확대
→ 원인 확인
→ 운영 결정
→ 결과 확인
→ 병원 전체 복귀
```

### 랜드마크

| 랜드마크 | 역할 |
|---|---|
| 중앙 운영 시계 | 병원의 하루 진행과 다음 일정 |
| 부서 이름판 | 공간 위치와 현재 상태 |
| 상태 배지 | 대기, 차단, 이벤트, 완료 |
| 병목 아이콘 | 현재 대기가 증가하는 핵심 원인 |
| 병상 현황판 | 1·2·6인실의 남은 병상 |
| 잠시 나가기 | 모든 운영 화면에서 고정 위치 |

랜드마크는 색상만으로 구분하지 않는다. 텍스트, 아이콘과 짧은 움직임을 함께 사용한다.

### 서브 경로

- 개별 환자의 대기 상태
- 의료진 일정과 피로
- 시설 점유와 남은 시간
- 병실별 남은 병상
- 향후 예약과 수술 일정
- 오래된 환자 안내 목록

서브 경로는 최대 두 단계 깊이로 제한하며 닫으면 이전 운영 화면으로 돌아온다.

## 4. 정보 계층

### 1단계: 지금 알아야 하는 것

- 현재 병원 시간
- 활성 이벤트
- 가장 큰 병목
- 운영 위험 경고
- 일시정지와 잠시 나가기

### 2단계: 결정을 위해 알아야 하는 것

- 부서 대기 인원
- 예상 대기시간
- 배치 의료진
- 처리 용량
- 차단 원인
- 다음 일정

### 3단계: 원할 때 자세히 보는 것

- 개별 환자 경로
- 의료진 전체 일정
- 지표 변화 이력
- 이벤트 결과 기록
- 병실 유형별 점유 내역

한 화면에서 세 단계 정보를 동시에 모두 펼치지 않는다.

## 5. 병원 전체 화면

### 세로 화면 구조

```text
┌────────────────────┐
│ 10:20  ⏸  잠시 나가기 │
│ 다음 일정: 수술 18분 후 │
├────────────────────┤
│  외래       검사실      │
│  대기 4     대기 2      │
│                       │
│  응급실     수술실      │
│  안정       준비 지연    │
├────────────────────┤
│ 병상  1인 0 · 2인 1 · 6인 1 │
├────────────────────┤
│ 가장 큰 병목: 외래 의사 부족 │
└────────────────────┘
```

### 부서 상태

- 안정: 아이콘과 `안정`
- 대기 증가: 사람 아이콘과 대기 수
- 차단: 잠금 아이콘과 한 줄 원인
- 이벤트: 이벤트 아이콘과 제목
- 완료: 체크 아이콘과 짧은 완료 효과

중요 이벤트가 발생해도 사용자의 카메라를 강제로 이동시키지 않는다. 해당 부서를 강조하고 탭하면 이동한다.

## 6. 부서 상세 화면

### 필수 정보

- 부서 이름과 전체 화면 복귀
- 현재 처리 중인 작업
- 대기열과 예상 대기
- 배치 의료진
- 시설 상태
- 가장 가까운 일정 충돌
- 가능한 운영 행동

### 차단 이유

한 작업에 여러 차단 조건이 있어도 가장 먼저 해결할 수 있는 이유 하나를 우선 표시한다.

```text
검사 대기 · 검사실 사용 중 · 8분 후 예상
수술 대기 · 선행 검사 미완료
입원 대기 · 남은 병상 0
외래 대기 · 담당 의사 이동 중
```

자세히 보기를 열면 나머지 조건을 확인할 수 있다.

## 7. 행동 전·후 피드백

### 행동 전

선택을 확정하기 전에 방향성 정보를 보여준다.

```text
응급실에 의사 지원
좋아짐: 응급실 대기, 환자 안전
주의: 외래 대기, 의료진 피로
이동 준비: 게임 시간 5분
```

### 행동 직후

1. 선택 버튼이 즉시 반응한다.
2. 의료진 또는 상태 카드가 새 위치로 이동한다.
3. 바뀐 처리 용량이 강조된다.
4. 지표 변화와 원인이 2초 동안 표시된다.
5. 결과는 변화 기록에서 다시 확인할 수 있다.

저장 완료를 기다리느라 행동 피드백을 늦추지 않는다.

### 불가능한 행동

아무 반응 없이 무시하지 않는다.

- 카드가 짧게 흔들림
- 차단 이유 표시
- 가능한 대안 한 가지 제안

예시:

```text
지금 이동할 수 없습니다.
진행 중인 진료 4분 남음
[완료 후 이동 예약]
```

## 8. 인지선과 원인 표시

플레이어가 볼 수 있는 정보와 내부 계산을 구분한다.

### 반드시 보여야 하는 정보

- 환자가 기다리는 이유
- 작업을 시작할 수 없는 이유
- 의료진 이동과 준비시간
- 일정이 바뀐 원인
- 병상을 배정할 수 없는 이유
- 지표가 변한 원인
- 이벤트가 종료된 조건

### 내부에 둘 수 있는 정보

- 난수 시드
- 셔플백 내부 순서
- 매 틱 상태 갱신
- 저장 직렬화 과정
- 세부 가중치

내부 정보가 결과에 영향을 주면 사용자에게는 이해 가능한 원인 문구로 변환한다.

## 9. 이벤트 화면

### 구조

```text
[이벤트 제목]
현재 상황을 한 문단으로 설명

선택 A
좋아짐: ...
주의: ...

선택 B
좋아짐: ...
주의: ...

[결정하기] [잠시 나가기]
```

### 원칙

- 이벤트가 열리면 병원 시간은 멈춘다.
- 읽기 제한시간을 두지 않는다.
- 선택지는 2~3개로 제한한다.
- 실제 의료 판단처럼 보이는 용어를 사용하지 않는다.
- 예상 영향은 방향으로 표시하고 실제 결과는 결정 후 표시한다.
- 이벤트를 닫고 병원 상태를 확인한 뒤 돌아올 수 있다.

## 10. 튜토리얼

### 학습 목표

1. 병목 찾기
2. 의료진 배치
3. 행동의 부작용 확인
4. 환자 안내
5. 일시정지와 중단

### 단계 구조

```text
작은 문제 제시
→ 사용자가 결과 예상
→ 두 선택 중 결정
→ 즉시 결과 확인
→ 같은 원리를 다른 문제에 적용
```

손가락 아이콘을 따라 누르기만 하는 단계는 한 번을 넘기지 않는다. 마지막 튜토리얼 문제는 안내 없이 사용자가 해결한다.

### 잘못된 시도

- 실패로 처리하지 않는다.
- 왜 실행되지 않았는지 표시한다.
- 바로 정답을 누르게 하지 않고 현재 병목을 다시 강조한다.

---

## 11. 카메라와 화면 전환

### MVP

- 병원 전체 화면은 고정한다.
- 부서 탭 시 0.25~0.4초 동안 확대한다.
- 부서 전환은 짧은 감속 이동을 사용한다.
- 움직이는 환자를 카메라가 계속 따라가지 않는다.
- 한 번의 조작으로 병원 전체 화면에 복귀한다.

### 모션 줄이기

- 확대·축소 없이 즉시 화면 전환
- 반복 이동 애니메이션 제거
- 밝기 변화 최소화
- 카메라 흔들림은 모든 설정에서 사용하지 않음

자유 드래그 카메라는 MVP에서 제외한다. 후속 버전에서 병원 단면이 화면보다 커질 때만 데드존 기반 이동을 검토한다.

## 12. 중단과 이어하기

### 잠시 나가기

- 모든 핵심 화면의 같은 위치에 제공
- 선택 시 즉시 일시정지
- 저장 요청 후 홈으로 이동
- 저장이 진행 중이어도 메모리 상태를 유지하고 완료 상태를 홈에서 표시

### 백그라운드

- `visibilitychange`가 발생하면 즉시 일시정지
- 복귀 시 자동으로 시간을 진행하지 않음
- `계속하기`를 눌러야 재개

### 이어하기 화면

```text
10:42 · 검사 장비 점검 대응 중
외래 대기 4 · 검사 대기 3
마지막 저장: 방금 전

[이어하기]
[새로 시작]
```

활성 이벤트가 있으면 선택 전 상태로 돌아가며 병원 시간은 멈춰 있다.

## 13. 하루 결과

### 정보 순서

1. 하루 운영 평가
2. 종합 PX 점수
3. 여섯 개 지표
4. 잘한 결정 2개
5. 개선할 결정 1개
6. 병목 흐름 요약
7. 다시 운영하기 또는 홈

### 인과관계 예시

```text
잘한 결정
오후 의료진 휴식을 배정해 이후 처리속도 감소를 막았습니다.

개선할 결정
검사 일정 변경 후 안내를 갱신하지 않아 만족도가 6 감소했습니다.
```

점수만으로 사용자를 평가하지 않고 다음 시도에 사용할 정신 모델을 제공한다.

## 14. 접근성

- 핵심 터치 영역은 최소 44×44 CSS 픽셀을 기준으로 한다.
- 본문 글자는 기본 16 CSS 픽셀 이상을 사용한다.
- 색상만으로 상태를 구분하지 않는다.
- 모든 핵심 정보는 무음으로 이해할 수 있다.
- 시간 제한이 있는 읽기 또는 선택을 사용하지 않는다.
- 드래그 행동은 탭 선택 방식으로도 수행할 수 있다.
- 모션 줄이기와 음소거를 첫 화면에서 접근 가능하게 한다.
- 화면 확대 시 핵심 행동이 가려지지 않아야 한다.

## 15. 빈 상태와 오류 상태

### 대기 환자 없음

`현재 대기 환자가 없습니다. 다음 예약 환자 12분 후`

### 사용 가능한 의료진 없음

현재 업무와 남은 시간을 보여주고 완료 후 이동 예약을 제공한다.

### 저장 실패

- 플레이를 중단하지 않는다.
- 로컬 메모리에 최신 상태 유지
- 재시도 제공
- 기존 정상 저장본을 삭제하지 않음

### 저장 손상

- 이전 정상 저장본으로 복구 시도
- 복구할 수 없으면 새 게임 여부 확인
- 동의 없이 기존 데이터를 삭제하지 않음

## 16. UX 수용 기준

1. 첫 사용자가 3분 안에 의료진 배치와 결과 확인을 완료한다.
2. 사용자가 현재 가장 큰 병목을 5초 안에 찾는다.
3. 핵심 행동은 전체 화면에서 세 단계 안에 도달한다.
4. 불가능한 행동은 이유와 대안을 표시한다.
5. 이벤트 선택 중 게임 시간이 흐르지 않는다.
6. 모든 화면에서 잠시 나가기를 사용할 수 있다.
7. 백그라운드 복귀 후 자동 진행되지 않는다.
8. 색상이나 소리만으로 전달되는 핵심 정보가 없다.
9. 모션 줄이기에서 모든 핵심 전환을 애니메이션 없이 사용할 수 있다.
10. 결과 화면에서 사용자가 자신의 선택과 지표 변화 원인을 설명할 수 있다.
